# 计算草稿（calc-draft）ZTools 插件设计

日期：2026-09-23
状态：已与需求方逐节确认

## 1. 目标与范围

做一个 ZTools 插件"计算草稿"：在一个界面里输入多步计算，中间结果被保留并可被后续计算引用，像在草稿纸上做计算一样总览全局、随时拷贝任意计算结果。

### 已确认的需求

- 单栏流式列表，每行是一个可编辑的数学表达式
- 四则运算 + 括号 + 常用数学函数（`sqrt sin cos tan log ln abs round floor ceil min max pow` 等）
- 中间结果通过稳定 ID 自动引用（`#1`、`#2`…），也可点击将结果值注入当前编辑行
- 每个 ID 配色，依赖链路在草稿纸中一目了然
- 每个数字都是独立单元，单击即拷贝
- 多页草稿，每页独立持久化，像笔记本
- UI 采用 macOS 设计语言：无边框、大圆角、阴影层次感、卡片感、聚光灯式高亮
- 窗口本身由 ZTools 接管，插件只负责内容区

### 非目标（本期不做）

- 显式变量命名（`a = 5`）——仅 `#seq` 引用与点击注入
- 多栏看板、minimap 缩略图
- 可编程表达式（if / 赋值语句）
- 会话之外的导出（导出文本/图片）留作后续

## 2. 方案选型

选定 **方案三：jsep 轻量解析库 + 自研引用/求值**。

- 用 `jsep`（约 3KB）做表达式 → AST 解析
- 自研 evaluator 遍历 AST，解析 `#ref`、调用内置函数表、处理常量与运算符
- 对比自研完整 parser（工作量大）与 mathjs（包体 150KB+、错误信息不完全可控），jsep 在包体与掌控力之间最合适

## 3. 数据模型

```ts
type DraftDoc = {
  pages: Page[]
  activePageId: string
}

type Page = {
  id: string            // 稳定 UUID
  name: string          // 页签名，如 "未命名草稿"
  rows: Row[]
  createdAt: number
}

type Row = {
  id: string            // 稳定 UUID，创建后永不变
  seq: number           // 创建顺序序号（1,2,3…），用于显示 #N、配色
  expr: string          // 原始表达式文本
}
```

### 关键约定

- **`#N` 中的 N 是 `seq`（创建顺序），不是视觉行位置。** 插入、删除、拖拽排序均不重新编号 `seq`，已有引用不断链。
- 每个 `seq` 对应一个固定色（从调色板循环取色）。行的 `#N` 标签、该行结果、表达式中出现的 `#N` 引用使用同色渲染。
- 行间依赖不落库，求值时从 AST 动态解析 `#ref` 得出。
- 删除行后其 `seq` 不复用；引用已删除 `seq` 的下游行显示"未找到"错误。
- 编辑某行后，找到所有直接/间接引用它的行，按拓扑序重算；检测到环时该行组标记错误，不影响其他行。

## 4. 状态管理与持久化

- 顶层 `useReducer`，action 覆盖：增删行、编辑表达式、新建/重命名/删除页、切换页、行排序。
- 每次状态变更后对当前页做一次全页求值（预期几十到几百行，性能无忧）。
- 持久化：`localStorage` 单键 `calc-draft:doc` 存整个 `DraftDoc`，状态变更后 debounce 500ms 写入。
- 启动时读取；JSON 损坏则回退为空文档。

## 5. 表达式解析与求值

### 解析管线

```
expr 文本 → jsep() → AST → 自研 evaluator → number | EvalError
```

### jsep 配置

- 追加标识符字符 `#`，使 `#1`、`#12` 被 lex 成单个 name token
- 二元运算：`+ - * / ^ %`，其中 `^` 右结合
- 一元运算：`-`（负号）

### Evaluator 规则

| 节点 | 行为 |
|---|---|
| 数字字面量 | 直接返回数值 |
| `#N` | 按 `seq` 查当前页已求值结果；不存在或未算出 → `Error('未找到 #N')` |
| 函数调用 | 查内置函数表；参数个数不符 → `Error` |
| 常量 | `pi`、`e` |
| 二元/一元运算 | 浮点运算；除零 → `Error('除以零')` |
| 环 | 求值维护 `visiting` 集合，重复 → `Error('循环引用')` |

内置函数表：`sqrt sin cos tan log ln abs round floor ceil min max pow`（后续可扩）。

### 求值调度（每页）

1. 构建依赖图：解析每行 AST，收集 `#ref` 边。
2. 拓扑排序；有环的节点整组标记 `Error`。
3. 按拓扑序求值，缓存 `Map<rowId, number | EvalError>`。

### 错误呈现

- 行内结果显示红色短文案（如 `循环引用`、`未找到 #3`），不弹全局弹窗。
- 出错的行不阻塞无关行的正常显示。

## 6. 界面布局与交互（Spotlight / macOS 风格）

### 整体框架

- 内容区满铺 ZTools 窗口：深色半透明磨砂背景（`backdrop-filter: blur` + 深色底），大圆角 16–20px，柔和多层阴影。
- 若 ZTools 窗口本身无边框，内部再做一层内圆角卡片，确保"无边框 + 大圆角 + 阴影"层次成立。

### 纵向结构（单栏）

```
┌─ 顶部栏（毛玻璃，sticky）────────────┐
│ 页签横向列表： [草稿1] [草稿2] [＋]    │  ← 多页切换/新建，双击重命名
│ 当前页名 · 行数 · 依赖链图例色点       │
├──────────────────────────────────────┤
│  行1  #1│ expr_input…        │ = 12  │
│  行2  #2│ expr+#1…           │ = 24  │  ← #1 引用着色
│  行3  #3│ …                  │ = 5   │
│  …                                   │
├──────────────────────────────────────┤
│ 底部快捷条：+ 新行 · 快捷键提示 · 状态 │
└──────────────────────────────────────┘
```

### 行的视觉（卡片感 + 聚光灯）

- 每行是一张浅色半透明圆角卡片，行间距 8px；hover 轻微抬起（`translateY` + 阴影加深）。
- `#N` 标签：胶囊形色块，背景为该 seq 的专属色（低饱和 pastel），文字深色。
- 表达式输入：无边框透明输入框，等宽字体；输入中的 `#N` 自动染成对应色。
- 结果区：右对齐、大字号；每个数字是独立 `button`。
- **聚光灯**：聚焦/编辑中的行全亮，其余行 `opacity: 0.55`；被当前行依赖（直接或间接）的上游行用色环/描边微微高亮。

### 页签

- 横向胶囊页签；当前页高亮（白色文字 + 微光下划线），非当前页灰色弱化。
- 右侧 `＋` 新建页；页签 hover 出现 `⋯` 菜单（重命名 / 删除）。

### 交互细节

- `Enter`：确认当前行编辑并新建下一行（焦点移至新行）；`Shift+Enter`：仅确认编辑，不新建行。
- 行 hover 行级操作：`⧉ 复制表达式`、`⎘ 复制结果`、`⌦ 删除`、`↕` 拖拽排序（只改视觉顺序，`seq`/ID 不变）。
- **点击结果数字 = 复制**到剪贴板 + toast；**`Alt+点击`（或结果旁小箭头）= 注入**到当前聚焦输入框光标处。
- Toast：macOS 风格小胶囊，1.5s 消失。
- 空状态：居中淡色引导"输入表达式，回车开始计算 · 支持 #1 引用上文结果"。

## 7. ZTools 接入

- `plugin.json` 移除模板功能 `hello` / `read` / `write`，仅保留主功能：
  - `code: "calc"`，`cmds: ["计算", "草稿", "calc"]`（触发词可再商定）
  - 窗口尺寸建议约 720×840、居中（若 ZTools 侧可配）
- `App.tsx` 路由简化为 `calc` → `<CalcDraft />`；保留 `onPluginEnter/Out`，进入时加载持久化文档。
- 移除 `Hello/Read/Write` 组件与对应 preload 服务逻辑。

## 8. 快捷键

| 快捷键 | 行为 |
|---|---|
| `Enter` | 确认当前行并新建下一行 |
| `Shift+Enter` | 仅确认编辑，不新建行 |
| `Esc` | 取消当前行编辑焦点 |
| `Cmd/Ctrl+D` | 复制当前行结果 |
| `Cmd/Ctrl+Shift+N` | 新建草稿页 |
| `Cmd/Ctrl+Enter` | 在末尾插入新行 |
| `Alt+↑/↓` | 当前行上/下移动（视觉排序） |

## 10. 测试策略

- **引擎层（Vitest 单测）**：四则/优先级/函数/常量、`#ref` 解析、缺失引用、循环引用、拓扑顺序、插入删除行后引用稳定性。
- **状态层**：reducer 增删行 seq 不变、持久化序列化往返。
- **UI 手测清单**：点击复制、注入、聚光灯高亮、多页切换、刷新后恢复。

## 11. 依赖

- 运行时新增：`jsep`
- 开发新增：`vitest`
- 既有：React 19、Vite、TypeScript（不变更）

## 12. 成功标准

1. 输入多行表达式，`#N` 引用正确求值；中间插入/删除行后既有引用不断链、结果正确。
2. 每个 `seq` 配色一致，依赖链路肉眼可追踪。
3. 单击任意结果数字可复制并出现 toast；`Alt+点击` 可注入当前编辑行。
4. 多页草稿独立保存，关闭重开后内容恢复。
5. 界面呈现 macOS 风格：无边框、大圆角、阴影层次、卡片感、聚光灯高亮。
6. 循环引用、缺失引用、除零等错误在行内呈现且不破坏其他行。
