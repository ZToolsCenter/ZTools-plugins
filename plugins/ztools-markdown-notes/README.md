# zTools Markdown Notes

一个面向 zTools 的本地 Markdown 笔记插件。它复刻轻量、快速的 Markdown 笔记体验，但将正文和附件保存在用户可见的普通文件中，避免绑定插件私有数据库。

> 当前状态：V0.1 已发布，持续优化中。

## 项目缘起

从 uTools 迁移到 zTools 后，我没有找到符合自己使用习惯的 Markdown 笔记插件，于是借助 Codex 做了这个项目。目前主要以自用为主，也欢迎反馈使用中遇到的问题或改进建议；不过空闲时间有限，回复和处理可能不会很及时，还请理解。

## 核心原则

- Markdown 正文始终保存为真实的 `.md` 文件。
- 附件保存在工作区的 `.assets/` 目录中，并使用相对路径引用。
- 插件数据库只保存设置、工作区注册、置顶、最近打开和界面状态。
- 文件删除先进入工作区的 `.trash/`，不会直接进入系统回收站。
- 保存前检查磁盘版本，冲突时绝不静默覆盖。
- 面向低内存环境：启动不读取全部正文，不建立永久全文索引，不常驻监听整个工作区。

完整产品规格见 [docs/SPEC.md](docs/SPEC.md)，开发约束见 [AGENTS.md](AGENTS.md)。

## 技术栈

- zTools 插件
- Vue 3
- TypeScript
- Vite
- Vditor（计划用于即时渲染编辑）

## 开发

要求 Node.js 18+，推荐使用 pnpm。

```bash
pnpm install
pnpm dev
```

开发时只需在 zTools 中添加一次 `public/plugin.json`。该清单直接指向 `http://localhost:5173`；保持 `pnpm dev` 运行后，Vue 页面通过 Vite 热更新，不需要反复构建或重新导入插件。

构建：

```bash
pnpm build
```

构建产物输出至 `dist/`。构建脚本会自动将 `dist/plugin.json` 的入口改为 `index.html`，用于生产验证或发布；其入口、图标和 preload 均从 `dist/` 内按相对路径加载。

## V0.1 功能

- 多工作区及迁移后的自动重新关联
- 真实目录树和安全的文件操作
- Vditor 即时渲染与 Markdown 源码模式
- Markdown 导入、Markdown 导出和 HTML 导出
- 自动保存、草稿恢复和外部修改冲突保护
- 文件名、路径和正文搜索
- 图片与附件本地化管理
- 工作区本地回收站
- zTools 全局笔记名称入口

不在 V0.1 范围：标签、双向链接、知识图谱、ECharts、图片拖拽缩放、常驻文件监听和永久全文索引。

## 备份与恢复

工作区本身就是完整、开放的备份单元。退出插件或确认当前笔记已显示“已保存”后，复制整个工作区目录即可；不要只复制 `.md`，隐藏的 `.assets`、`.trash` 和 `.znotes-workspace.json` 也应一并保留。

- 恢复到原位置：把完整目录放回原路径，重新打开插件。
- 恢复到新位置：在设置的工作区管理中选择“重新关联”，选中备份目录；插件会核对稳定的工作区身份。
- 迁移工作区：插件完整复制并逐文件校验后才切换到新目录，原目录会保留为备份，不会自动删除。
- 误删笔记：先在插件回收站中恢复；回收站也包含在完整工作区备份内。
- 异常退出：重新打开对应笔记后，可在草稿提示中对比磁盘版本并决定恢复，不会自动覆盖磁盘文件。

## 数据同步

- 插件设置和工作区注册信息：使用 zTools 提供的插件数据同步能力。
- `.md`、`.assets` 和 `.trash`：由用户使用 Git、OneDrive、Syncthing、NAS 等文件同步方案管理。
