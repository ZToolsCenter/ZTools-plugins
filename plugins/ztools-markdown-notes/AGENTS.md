# AGENTS.md

本文件约束所有在本仓库中工作的自动化编码代理和贡献者。

## 开始工作前

1. 完整阅读本文件和 `docs/SPEC.md`。
2. 检查现有代码、测试和工作区状态。
3. 只实现当前任务明确要求的范围；产品行为不明确时先更新或确认规格。
4. 若实现与 `docs/SPEC.md` 冲突，以规格为准，不得静默改变产品定义。

## 不可违反的产品规则

- 正文必须保存为用户工作区中的真实 `.md` 文件，禁止把正文迁入 zTools 数据库。
- `.assets` 和 `.trash` 属于工作区保留目录，普通目录树必须隐藏，常规文件操作不得重命名、移动或删除它们。
- 从插件移除工作区只能取消关联，禁止删除对应磁盘目录或内容。
- 删除笔记或目录必须先移动到当前工作区 `.trash`；永久删除、清空回收站和附件清理必须经过明确确认。
- 删除笔记时禁止连带删除附件。未使用附件只能经过全工作区引用扫描、展示清单并由用户确认后清理。
- 任何写文件操作都必须执行磁盘版本检查，并采用临时文件写入后原子替换。冲突、权限错误和保存失败不得静默处理。
- 禁止使用绝对路径创建工作区内链接或跨工作区链接。跨工作区定位必须使用稳定的 `workspaceId + relativePath`。
- 不得默认引入常驻工作区监听、永久全文索引或全正文内存缓存。

## 技术约束

- 使用 Vue 3、TypeScript 和 Vite。
- Vue 代码默认使用 Composition API 和 `<script setup lang="ts">`。
- 本地文件系统能力放在 preload/Node 边界，渲染层不得散落直接文件操作。
- preload 暴露最小、明确、可类型检查的 API；路径校验和数据安全逻辑应在可信边界内完成。
- 编辑器首选 Vditor IR。只有在验证 Vditor 无法满足已确认行为后，才讨论引入 CodeMirror 等第二编辑器。
- zTools API 的使用必须以当前官方文档或仓库类型定义为依据，不凭记忆猜测。
- 优先使用 Web 标准和小型纯函数，不为假想的未来需求建立抽象层。

## 代码组织

- 按领域职责组织模块，例如工作区、文件树、笔记存储、附件、回收站、搜索和 zTools 集成。
- UI 组件不直接拼接磁盘路径或实现文件安全策略。
- 路径统一使用规范化的工作区相对路径作为业务标识；Windows 绝对路径只存在于工作区注册和文件系统边界。
- 数据结构和公共 API 需要明确 TypeScript 类型。

## 验证要求

- 每次改动都应有可验证的完成条件。
- 至少执行与改动相关的类型检查、测试和生产构建。
- 文件操作功能必须覆盖成功、同名冲突、外部修改、无权限和跨路径逃逸等风险场景。
- 不得用测试中的类型断言掩盖不完整数据模型。
- 若环境无法执行某项验证，交付时明确说明未验证的部分和原因。

## 变更纪律

- 保持改动小而集中，不顺手重构无关代码。
- 不擅自增加 `docs/SPEC.md` 明确排除的功能。
- 产品决策变化时，先同步更新 `docs/SPEC.md`，再修改实现和测试。
- 不提交密钥、用户笔记、绝对工作区路径、构建产物或依赖目录。
