## 1.4.0 - 2026-10-27

### Performance

- 修复「打开插件后 ZTools 卡死/卡得用不了」的深层根因：ZTools 隐藏插件视图时只挂起渲染、**不销毁视图**（日志 `Plugin WebContentsView 已隐藏，缓存保留`），每次打开都新建一个视图。每个缓存隐藏视图的 preload 调度器仍以 1 秒间隔持续向主进程发起同步 IPC（读锁 + 心跳写锁），视图越积越多，主进程被拖垮后整机卡顿
  - `lib/scheduler.js` 增加可见性感知调度：插件视图可见时保持 1 秒精度；隐藏到后台时降频到 60 秒（触发误差 ≤60 秒，即用户可接受的一分钟上限），每个隐藏视图的同步 IPC 压力较优化前下降约 98.5%；同步把调度锁 TTL 从 8 秒放大到 180 秒，防止多个隐藏视图因心跳变稀互相抢锁导致重复提醒
  - `preload.js` 接入 ZTools 生命周期事件 `onPluginOut`（隐藏 → 降频 / 被杀 → 停表）与 `onPluginEnter`（进入 → 恢复 1 秒并立即对齐状态），并以 `document.visibilitychange` 兜底；API 不可用时自动回退为默认 1 秒调度
  - 不彻底停摆调度器：持锁窗口仍需在后台准点触发提醒，锁竞选 / 补发 / 弹窗升级机制保持不变

## 1.3.1 - 2026-10-26

### Performance

- 大幅降低插件对 ZTools 的同步数据库压力，修复「打开插件后 ZTools 卡顿」：`ztools.db` 为同步桥接（每次调用阻塞渲染进程主线程），原实现每个插件窗口的调度器**每秒**执行 3 次读库（读锁 + 读设置 + 全量读提醒列表），多窗口 / 长时间运行时开销随窗口数量成倍放大
  - `lib/store.js` 增加短 TTL 内存缓存（提醒列表 4 秒、设置 30 秒），所有写操作即时失效：全量读库从每秒一次降至每 4 秒一次，设置读取不再逐秒执行；跨窗口变更最多延迟约 4 秒可见，与原有指纹轮询机制兼容
  - `index.js` 页面不可见时跳过每秒倒计时与状态渲染（保留跨窗口指纹轮询），进一步降低隐藏窗口的 CPU 占用
  - 缓存失效覆盖创建 / 更新 / 删除 / 设置变更全部写路径，触发、补发、多窗口锁等行为不变（自测全绿）

## 1.3.0 - 2026-10-12

### Added

- ICS 日历导入 / 导出（iCalendar RFC 5545）：待提醒页「导入日历 ICS」、已完成页「导出日历 ICS」，可与系统日历 / Outlook / Google Calendar 互通，也用于跨设备迁移
  - 导出：每条提醒一个 `VEVENT`，重复规则映射 `RRULE`（间隔 / 每小时 / 每天 / 每周 / 工作日 / 每月，支持 `COUNT` 与 `UNTIL`），生效时段以 `X-ACTIVE-WINDOW` 保留，附 `VALARM` 到点提醒，已停用 / 已完成导出为 `STATUS:CANCELLED`
  - 导入：解析 `VEVENT` 并还原重复规则，兼容 UTC / 本地 / 纯日期三种时间形式；`YEARLY` 等不支持的频率按无效跳过，已过期的单次事件导入为已完成
- 工作日提醒接入中国法定节假日与调休（`lib/holidays.js`，覆盖 2025–2026 年）：`workday` 重复规则按「调休上班日 > 放假日 > 普通周一~周五」判断，法定节假日不误触发、调休上班的周末正常触发；数据未覆盖的年份自动退化为普通周末判断，设置页「调度器」显示节假日数据覆盖年份

### Fixed

- 修复「补发错过的提醒」设置（`notifyOnMissed`）从未生效的问题

- 修复「这周五/本周五」在周五当天被解析为下周五；当天时刻已过时自动顺延到下周五
- 修复设置浅合并导致旧版本数据缺少新字段（如 `channels.webhook`）的升级兼容问题，改为深合并
- 修复多窗口（分离窗口等）列表不实时同步：按数据指纹检测变化后自动重建
- 修复弹窗「稍后 10 分钟」写死时长，现跟随设置中的 `snoozeMinutes`
- 修复开发预览服务器路径穿越检查可被同前缀目录绕过（如 `ztools-evil`）

### Added

- 网络请求支持环境变量代理（`HTTPS_PROXY` / `HTTP_PROXY`，遵循 `NO_PROXY`；HTTPS 走 CONNECT 隧道，支持代理认证），大模型 / 短信宝 / Webhook 在需要代理的网络下可用
