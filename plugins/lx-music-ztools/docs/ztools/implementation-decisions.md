# 实施取舍记录

此表按实施ledger的决定顺序整理，保留理由和判断错误的代价。不是把限制项写成已通过。

| 决定 | 理由 | 判断错误的代价/边界 |
| --- | --- | --- |
| 使用用户指定的现有独立仓库和干净功能分支，不另建worktree | 用户明确指定目录；原桌面仓库只读参考 | 隔离依赖该分支和命名文件提交；若同时有人在此目录改代码，需要重新核对冲突 |
| 保留src-ztools清单/打包工具，Vite诊断与原UI的Webpack并存；计划路径映射到preload/runtime | 延续已验证框架和发布工具，不换前端 | 两套构建入口需要同时维护；产品入口固定为dist/lx.html |
| 最初P0使用已安装app.asar+独立Electron42并记录实际版本 | 先得到真实插件环境证据 | 不代表3.2源码宿主或日常EXE；42后续长测失败保留，41.4匹配运行时另验 |
| guest不可用后固定CSP浏览器Worker，使用同步JS crypto；fixture用显式递归复制 | 目标宿主实际guest未初始化；同步工具与外部终止已证明；此Node环境fs.cpSync异常 | 依赖DOM的第三方源不兼容；新增宿主需重验隔离、网络和crypto |
| 结构化数据使用pluginData+内置SQLite，复用原SQL事务 | 宿主云db批量可部分成功；SQLite事务回滚/重开已实证 | 需要具备node:sqlite的宿主；ZTools账号云切换不会自动同步曲库，使用备份/显式LX同步 |
| 剩余大模块改为单一implementer顺序实施、父共享集成和独立只读复核 | 下载/同步有跨阶段状态与并发风险 | 成本是额外审查；文件所有权和跨模块契约需在集成时统一验证 |
| 元数据在可信隐藏宿主窗口执行，Node测试保留Worker后端 | 目标插件renderer的worker_threads实际不可用 | 元数据期间增加临时renderer；只加载可信写标签代码，绝不执行用户音源 |
| 将历史旧URL错误删除新任务的路径视为本次下载依赖问题并修复 | 同ID重启会受到旧异步失败影响 | 扩大到原下载UI动作的代次保护，需要重新验证取消/最终化与数据库提交 |
| 原桌面源码不安装依赖/重跑独立安装器，以736个Git blob内容核对和独立web构建验证修改边界 | vendor无语义修改，只有689个文件CRLF/LF差异；所有适配在外部 | 不声称原完整桌面发行包构建已运行；后续若修改vendor或桌面入口，需补对应构建 |

核心长测在主题/歌词最终修正前的同一播放/下载服务检查点运行；最终ZIP另通过完整专项和50次短生命周期回归。人工听音、物理快捷键与日常EXE环境仍明确未验，不能由自动化替代。

保留现有功能分支和已提交实现；本轮交付本地安装包，未再次推送或发布。此前0.0.2送审状态不代表0.1.0已经上架。
