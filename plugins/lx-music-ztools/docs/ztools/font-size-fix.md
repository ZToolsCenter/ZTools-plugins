# 0.1.2 字体大小修复与验证

发布说明：下文记录2026-11-10的本地修复与当时不发布的要求。用户已于2026-11-11授权推送GitHub并提交市场更新；不将本地验收等同于市场审核通过。

日期：2026-11-10。用户反馈基本设置的六档字号没有改变页面文字；本轮不推送GitHub、不发布市场。

## 原因

原LX使用`postcss-pxtorem`，把文字、间距及关联尺寸从px转换为相对根字号的rem（基准16）。移植Webpack只接了Less和CSS处理，遗漏这一步。因此`common.fontSize`能够保存、`html.style.fontSize`也改变，但正文仍是固定14px，搜索输入仍是固定13.5px。

上轮根字号与存储断言不足以证明文字变大，本次明确补上实际计算字号、字宽及布局检查，不把旧断言当作渲染通过证据。

## 修改

- `build-config/ztools/postcss.config.cjs`保留上游的转换范围、16px基准及选择器排除，不修改`vendor/lx`。依赖目录排除改为插件6.1.0实际支持的正则写法；上游数组写法对此版本无效，范围回归先复现了第三方CSS被误转，再验证修正。
- Webpack在Less之后、css-loader之前执行PostCSS，普通CSS和CSS Modules共用。宿主外框的`html`规则保留，桌面歌词等运行时显式px字号不由该构建步骤改写。
- 版本升为0.1.2；精确声明构建依赖，不增加插件运行时依赖。
- `scripts/test-font-size.mjs`从原设置控件切换六档，直接测量正文、选项标签、搜索输入及导航文字；再验证切页和公开终止/重开。
- 原`scripts/test-settings.mjs`在保存/根字号之外，补充正文计算字号断言，防止再次出现保存成功但正文未缩放。

## 实际测量

测试使用隔离数据的真实ZTools3.3.0-beta.2 app.asar与匹配的Electron41.4.0。下表为CSS计算字号，截图中的物理像素还受系统缩放影响。

| 选择 | 根字号 | 设置正文 | 搜索输入 |
| --- | --- | --- | --- |
| 更小 | 14px | 12.25px | 11.8125px |
| 小 | 15px | 13.125px | 12.6562px |
| 标准 | 16px | 14px | 13.5px |
| 大 | 17px | 14.875px | 14.3438px |
| 更大 | 18px | 15.75px | 15.1875px |
| 非常大 | 19px | 16.625px | 16.0312px |

修复前同一测试明确失败：根字号14→19，但设置正文始终14px、搜索输入始终13.5px。修复后六档文字按比例变化、可见字宽增长，容器持续铺满宿主内容区域。切到搜索页再返回，以及`outPlugin(true)`后重新进入，均保留19档及其实际正文渲染大小。

证据：`artifacts/font-size/before-fix.json`、`report.json`、`size-14.png`、`size-19.png`。真实安装包复验和最终校验值以本文后续记录为准；不改日常ZTools数据。
