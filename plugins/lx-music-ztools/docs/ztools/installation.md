# 安装、使用与数据迁移

适用目标：0.1.2，Windows x64，第三方原生移植版。实际宿主验证组合及尚未完成的项目见 [兼容矩阵](compatibility.md)。当前版本不作市场已上架声明。

## 安装本地包

1. 源码构建执行 `npm ci`、`npm run build:ztools`、`npm run pack:ztools`。构建安装插件独立运行依赖并检查资源与许可。
2. 在 `dist-ztools/` 找到 `lx-music-ztools-0.1.2.zip` 及 `.zip.sha256`。用 `Get-FileHash -Algorithm SHA256` 比对旁边校验值；包内 `build-info.json` 记录文件清单与逐文件 SHA256。
3. 打开 ZTools「设置 → 插件应用 → 导入本地插件」，选择 ZIP，确认安装、启用。
4. 搜索 `lxmusic`、「LX Music」或「洛雪音乐」打开。首次阅读并接受原使用协议，再导入自己的音源。

开发方式是注册 `src-ztools/plugin.json`，随后安装并启用开发项目。生成文件、选中目录或在隔离测试实例安装均不会自动安装到日常使用的 ZTools。默认播放器入口为 `dist/lx.html`，`dist/index.html` 是诊断页。

从旧版更新后，终止当前已打开的LX插件，再通过`lxmusic`重新进入，确保加载新样式。0.1.2恢复了六档字体大小的实际文字缩放，旧页面不会自动替换内存中的样式。

运行包自带 `preload/node_modules`，不依赖开发目录或另装 LX 桌面版。不支持内置 `node:sqlite` 或缺少所需公开 API 的宿主会报告错误；当前不承诺所有旧版 ZTools 兼容。

## 导入与选择音源

进入原 LX 设置 → 自定义源管理，通过「本地导入」选择 JS 文件，或「在线导入」输入用户自备 HTTP(S) 地址，导入后选择该源。插件不预置、下载推荐列表或分发第三方音源。更新插件也不会把测试者的本地音源打入包。

音源使用 LX API 2.0.0 契约，在 CSP 浏览器 Worker 中初始化和执行，通过受控桥进行 HTTP/取消请求。Worker 没有 DOM、Node require 和 ZTools API；依赖 `window`/`document` 的脚本可能初始化失败。切换源会隔离旧请求结果。脚本初始化成功、搜索有结果和能够获得可播放 URL 是不同环节。

真实样本曾导入 23 个去重脚本，其中 20 个初始化成功，3 个因 DOM 依赖或外部服务等原因失败；仅指定 `monster.js` 样本的 `kw_228908` 已实际播放并下载成功。这不是全部脚本、全部歌曲或全部平台的保证。请只导入自己信任并有权使用的脚本；源码仓库和产品 ZIP 不保存这些原始脚本、URL 或凭据。

## 隐藏、分离与终止

关闭/隐藏插件视图后，原播放器继续播放，下载队列以及显式启用的同步和开放 API 继续服务。再次进入复用同一插件实例；分离窗口由 ZTools 管理。需要停止整个插件时使用 ZTools 的终止插件功能。终止会释放自身请求、音源会话、歌词窗口、监听端口及数据库资源。操作系统退出、宿主终止或崩溃不保证继续后台运行。

快捷键页提供「LX 播放/暂停」「LX 上一首」「LX 下一首」「LX 搜索」「LX 桌面歌词」的宿主设置入口；搜索框可输入 `lx 搜索 歌曲名`。真实物理按键和系统媒体键未经完整验收，详见 [能力边界](host-capabilities.md)。

## 下载目录与恢复

在原下载设置启用下载，通过目录选择器授权一个可写的目录，配置文件名、并发、跳过已有文件、歌词和标签选项。导入备份中的路径不会自动获得该目录的文件访问授权，迁移后需重新选择。

**所有新下载都需要目标文件系统支持 hard link**，即使已选择覆盖也一样；建议使用本地 NTFS。FAT/exFAT、网络盘或受限目录可能失败，不会退化为暴露半成品的非原子复制。不要手工删改下载中的私有 `.part`/恢复文件。

续传需要资源身份、URL、validator 和落盘长度匹配。服务端忽略 Range、validator 不可靠或资源变化时会保守重下；连续 403/410、断流等按最多初次加两次的预算终止。MP3/FLAC 标签与封面在私有副本完成并回读校验后原子替换；WAV/APE 不承诺同样的标签能力。歌词支持原/翻译/罗马音及 LX 扩展，按 UTF-8 BOM 或 GBK 保存。

重启会检查已发布文件的 inode/设备号、大小和 SHA256。**标签副本 rename 已完成、新 fingerprint 尚未落盘之间的崩溃窄窗**会保守报 `ownership`/外部修改错误并保留音频，不会自动认领或删除。遇到此错误先审阅保留文件，选择新文件名或明确覆盖后再试。删除下载任务不删除已发布的最终音频；用户替换的文件不因内容相同就被当成本任务所有。

## 本地数据、备份与迁移

列表、收藏、下载记录、不喜欢、歌词/URL/换源缓存、设置保存在 ZTools `getPath('pluginData')` 对应的设备本地目录及 SQLite，音源配置也是设备本地。它们与 ZTools 账号云同步独立，切换账号不会自动完成音乐数据迁移。

优先在原「备份与恢复」导出全部数据、列表或设置，再在新设备显式导入。支持原旧版/当前版 LX 备份及 gzip，全部数据恢复将设置与列表放在同一 SQLite 事务中。原 TXT/CSV 歌单导出也可用。这里的「全部数据」按原备份格式是**设置与列表**，不包括本地音频、已下载文件、用户音源原始脚本、同步认证或所有缓存。音乐文件和合法持有的脚本应自行另外保管，新设备重新授权目录并导入脚本。

若需多设备同步，在原同步设置选择 client/server，按页面填服务地址/端口和认证码，确认首次列表/不喜欢合并方式，随后显式启用。默认不开监听。已验证官方 LX Desktop 2.12.6 在同机 localhost 两个方向互通；外网、移动版本、全部冲突模式及长期运行仍需另验。同步只覆盖原协议协商的数据，不传音频或用户脚本。list/dislike 并非跨模块分布式原子事务；模块失败会报错，已提交的另一模块可能保留。

## 开放 API

在原设置显式开启，默认端口为 23330；可读取 `/status`、订阅 `/subscribe-player-status` 并调用原播放控制接口，操作的是同一播放器。默认绑定本机，只有主动选择局域网绑定才对局域网开放。沿用原接口访问模型，不新增认证能力；端口冲突会报错，停止服务或终止插件释放监听。

## 排错与卸载

| 现象 | 检查方式 |
| --- | --- |
| 搜索不到插件 | 检查是否在当前 ZTools 实例安装并启用，确认 ZIP/manifest 版本和关键词 |
| 启动提示 SQLite/预加载失败 | 检查宿主与 Node 能力及包完整性，重新进入；独立测试宿主曾有预加载未注入的冷启动记录，不能视为已解决 |
| 音源初始化失败或不能播放 | 区分 Worker DOM 限制、源能力、URL 解析与外部服务故障；搜索结果不证明播放地址有效 |
| 只能使用默认音频输出 | 当前宿主可能不提供 mediaDevices 枚举能力；不承诺输出设备切换 |
| 下载失败/归属校验错误 | 检查目录授权、hard link 支持、磁盘空间和是否外部修改；保留已有文件，按上述恢复说明处理 |
| 同步/API 无法启动 | 检查端口占用、地址/认证、原冲突选择；只在显式启用后检查监听 |
| 隐藏后仍有播放或端口 | 这是后台行为，使用宿主终止插件才会停止整个服务 |

卸载前导出需要的数据并另外备份音频和脚本，终止插件后从 ZTools 插件应用中卸载。是否清理插件本地数据以宿主卸载选项为准；下载目录中的最终音乐不属于插件安装目录。重新安装不等于恢复被清理的 SQLite 或音源。
