# 安全模型

垃圾清理属于破坏性本地操作。本插件把误删风险视为主要安全边界，并采用“宁可漏清，不可扩大删除”的策略。

## 信任边界

- UI 为不可信调用方，只能提交扫描返回的 `snapshotId` 和随机 `candidateId`。
- UI 不能提交文件路径、命令、通配符、递归深度或扫描根目录。
- preload 只暴露扫描、取消、清理、定位和复制结果五个业务方法，不暴露 `fs`、`child_process` 或 Electron 模块。

## 删除边界

1. 根目录由可信 Home 的固定平台结构推导，不接受环境变量扩权。配置路径必须先通过非 symlink/junction 的 `lstat`，再与 realpath 后目录核对设备号和 inode。Home 外只允许固定 `/tmp` 或符合 macOS 用户临时目录结构的根，并逐项复核所有者。
2. Home、临时目录本身、文件系统根目录、根目录的兄弟目录均不能成为候选项。
3. 只枚举白名单根目录的直接子项；大小统计不跟随符号链接。
4. 候选项必须与扫描根目录处于同一设备，防止意外挂载点进入清理范围。
5. 需要所有权复核的临时目录会遍历检查候选及其全部后代；执行前重新解析 realpath、lstat、所有权、根指纹和整棵目录树的元数据摘要，任一变化即拒绝。
6. 清理快照两分钟过期、一次性使用，并要求用户输入固定确认文本；扫描与清理共用全局执行门闩，禁止跨快照并发删除。
7. 所有成功操作使用系统废纸篓；单项失败不会扩大权限或改用永久删除。

## 不做的事情

- 不调用 `sudo`、UAC、提权脚本或 shell 拼接命令。
- 不清理系统缓存、系统日志、交换文件、数据库、软件包或其他用户目录。
- 不根据模糊名称猜测个人文件是否“无用”。
- 不上传扫描结果、路径或使用数据。
