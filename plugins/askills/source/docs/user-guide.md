# Askills 使用指南

本指南对应当前开发预览版。Askills 已提供本地 skills 库、项目扫描与部署、GitHub 公共来源导入；支持中英文界面，skill 正文保留原文。

请在 **Tauri 桌面窗口**中操作。开发环境运行 `pnpm tauri dev`；`pnpm dev` 打开的浏览器页面只用于界面预览，不能选择本地目录或管理项目文件。

## 1. 把本地 skill 保存到 skills 库

也可以先打开项目详情，点击“添加 skills”：从 skills 库选择已有版本，或切换“从云端 / 从本地”。新导入的 skill 先保存到库，再继续当前项目的安装预览；全程保留项目选择，点击“确认应用”才部署。

skill 详情中的“编辑显示名称”可给 skill 起中文别名（最多 80 字符），也可恢复原名。搜索同时匹配别名和原始名称；别名不修改 `SKILL.md`、版本快照或项目安装路径，重新导入和重启后保留。

右键 skill 卡片可重命名、删除、进入多选或添加到项目。进入多选后通过勾选框/点击卡片选择，顶部工具栏可以全选、清空、批量删除或批量添加；搜索时清空选择，避免对已隐藏的搜索结果误操作。右键添加和批量添加使用各 skill 的最新版本，先预览目标项目、Agent 目录与每项路径，再确认添加。失败项可重新预览后重试，成功项不重复安装；同批次安装路径相同的 skill 会阻止写入。

删除需要确认，采用**从列表移除、保留快照**的方式：已经安装到项目的 skill 继续可用，来源目录也保留；重新导入同一来源恢复列表和历史版本。删除不会释放版本快照的磁盘空间。

键盘聚焦卡片后可以按 `Shift+F10` 或菜单键打开菜单，用上下方向键选择、`Enter` 执行、`Esc` 关闭。点击菜单外部、滚动页面或切换页面时关闭菜单。其他页面和区域禁用默认右键菜单；复制/粘贴仍可使用键盘快捷键。

1. 打开“skills 库”，点击“导入本地 skill”。
2. 在系统文件夹选择窗口中选择**直接包含 `SKILL.md` 的目录**，而不是整个项目或多个 skill 的父目录。
3. 检查预览中的名称、描述、文件数量、大小、许可证与正文。如果出现缺少文件或引用越界的错误，先修正来源目录后重新选择。
4. 点击“确认导入”。Askills 复制整个 skill 目录并保存内容快照，原始目录保留不变。

最小目录示例：

```text
my-skill/
  SKILL.md
  references/
    guide.md
  scripts/
    helper.py
```

`SKILL.md` 需要有效的 YAML frontmatter，例如：

```markdown
---
name: my-skill
description: 描述这个 skill 适合解决的问题。
---

# 使用说明
```

skill 中的普通文件、脚本、附件和空目录随快照保存，但 Askills 不执行脚本。来源包含符号链接、junction 等重解析点时会拒绝导入。Markdown 的本地引用必须存在且留在 skill 目录内；例如 `../../shared.md` 越出 skill 根目录时不能直接导入。

点击 skill 卡片可阅读 `SKILL.md`，切换“原始 Markdown”或选择历史“阅读版本”。当前阅读器不会执行 HTML、加载图片或打开正文链接；附件保存在快照中，尚未提供附件浏览器。

从**同一个来源目录**再次导入相同内容会复用已有版本；内容改变后生成新版本。已经安装到项目的版本保持不变，需要另行选择升级。当前不支持把同一来源的 skill 名称改成另一个名称后直接作为原 skill 升级。

有多个版本时，“对比最新版本”展示新增、删除、修改的文件路径，以及两份 `SKILL.md` 正文。它是版本比较，不是代码审查或安全认证。

可到“设置 → 本地 skills 库 → 选择 skills 库位置”更改存储目录，包括已经导入内容的库。选择专用的空目录或空的 Askills 库，确认预览中的当前路径、目标路径、skills/版本/项目安装数量和大小，再点击“确认迁移”。目标不能与旧库、应用数据或已登记项目目录重叠，也不能合并另一个非空库。

迁移会先复制并校验全部内容，再更新受管理项目链接和当前库位置；项目使用的版本保持不变。复制期间可以在顶部通知中取消，切换开始后会先安全完成。迁移成功后，原目录保留作备份：先验证阅读、导入和项目扫描正常，再自行删除原目录。不要直接在资源管理器中移动正在使用的库。

预览取消不会迁移。失败时按顶部错误提示处理，再重试；如果提示目标内容被外部修改，不要直接覆盖或删除目标文件，应先核对保留的内容。

## 2. 登记项目、检查 skill 并选择版本

### 添加与扫描项目

右键项目卡片可以“备注项目名”“删除”“多选”“添加 skills”。备注最多 80 字符，仅用于显示，路径和文件夹名不变；留空或“恢复原名”清除备注。“添加 skills”直接进入该项目的 skills 库/云端/本地选择器。多选工具栏支持批量删除。

删除项目仅将其移出管理列表，保留项目文件、已安装 skill 和管理记录；再次添加同一文件夹时恢复原项目身份、备注和部署关系。需要停用某个 skill 时，请使用项目详情中的“停用”。

- 点击“项目 → 添加项目”，在系统对话框中选定一个项目文件夹。项目不必使用 Git。
- 或点击“扫描目录”，选择一个包含多个项目的父目录，从发现结果中勾选要登记的项目。当前项目发现使用限定深度，识别 Git 工作区（包括 `.git` 为文件的 worktree）和已知 skill 目录。
- 点击项目卡片进行扫描；“重新扫描”重新读取磁盘上的现状。发现列表会显示入口路径、链接解析目标、可能读取它的工具及诊断信息。

扫描跳过常见依赖、构建目录和目录链接，不扫描整盘，也不读取 Codex、Cursor 的私人聊天历史。现有 skill 仅被只读展示，登记项目不会自动接管或改写它们。

当前可以将 skill 部署到以下项目入口：

- Codex：`.agents/skills/<name>/`。
- Cursor：`.cursor/skills/<name>/`。
- Claude Code：`.claude/skills/<name>/`。

扫描还会识别兼容入口和嵌套作用目录。**选择 Agent 不等于只让该 Agent 看到 skill**：例如 Cursor 也可能读取 `.agents/skills/`、`.claude/skills/` 等兼容路径。请依据实际写入路径和“可能读取”提示判断影响范围。

### 启用与升级

1. 回到“skills 库”，打开一个 skill，选择要使用的“阅读版本”。
2. 点击“添加到项目”，选择项目、Agent 目录和部署方式。
3. 点击“预览变更”，核对实际目标路径、版本、冲突和提示。
4. 没有冲突时点击“确认应用”。应用前会再次检查版本内容与目标入口；过期或已变化的预览需要重新生成。
5. 到对应 Agent 中刷新或开启新会话，实际确认 skill 已被发现。Askills 的文件校验成功不代替 Agent 的真实加载验收。

对已管理的同名、同来源入口选择另一个版本，会进入升级确认。只改变所选项目；skills 库增加新版本不会使其他项目自动升级。

部署方式的含义：

- **自动选择**：优先创建目录符号链接；Windows 上失败时尝试 junction，再失败时使用复制。完成提示会显示实际采用的方式。
- **复制**：项目内保存独立副本。适合计划提交到 Git、在容器或远程环境中使用、或要共享给其他电脑的项目。是否把文件提交到 Git 仍由你决定，Askills 不自动提交。
- **符号链接**：入口指向本机 skills 库中的固定版本。明确选择此模式时，权限不足会报错，不自动改用其他模式。
- **Windows junction**：Windows 目录链接方式。只在支持的本地路径上使用；明确选择后创建失败会报错。

链接目标是固定快照，不是不断变化的“最新版”。本机绝对链接不能随 Git 自动带到另一台电脑，网络共享与不同运行环境也可能无法读取它；此时优先选复制。

项目生成的 `askills.lock.json` 记录来源、内容摘要、相对安装路径和实际模式，不记录本机 skills 库根目录或凭据。当前可以用它检查期望状态，**尚未提供在另一台电脑上读取锁文件并自动重建安装的向导**。已存在未知格式或与本机记录不一致的锁文件时，Askills 会停止并提示，不覆盖它。

### 回滚与停用

在“项目”中选择项目，找到“由 Askills 管理”的 skill：

- “回滚”恢复该入口的上一个受管理版本；没有历史版本时不可用。
- “停用”移除这个项目的受管理入口，保留 skills 库快照和来源文件。使用链接时只移除链接本身，不删除链接目标。

外部已有的同名文件夹不会被覆盖。复制副本被编辑、入口被替换、父目录变为链接、skills 库快照发生漂移时，升级或停用会停止。先保存自己的修改，再根据提示处理差异；当前没有“强制覆盖”或自动接管外部内容的按钮。

## 3. 从 GitHub 导入：API / 本地 Git

1. 打开“来源”，选择“GitHub API”或“本地 Git”，填写 `owner/repository` 或 `https://github.com/owner/repository`。项目“添加 skills → 从云端”也提供这两个方式。
2. 在独立输入框填写分支、标签或完整 commit；留空使用仓库默认分支。这里填写仓库地址，不是某个 `tree/...` 子目录链接。
3. 点击“查找 skills”。Askills 将版本解析为完整 commit，并列出该提交中发现的 `SKILL.md` 候选目录。
4. 每项都有“下载 / 预览 / 多选”。“下载”直接校验并保存到 skills 库；“预览”仅临时读取内容，关闭不会入库，预览中也可点击“下载到 skills 库”。
5. 点击“多选”或“全选”，再“下载所选”即可按顺序批量保存。成功项退出选择，失败项保留错误和重试入口；取消后不再处理下一项。批量操作不自动安装到项目。

点击“查找 skills”时，格式合法的仓库地址会保存到页面下方、推荐仓库上方的“历史记录（最近10条）”。历史与推荐仓库采用相同的按钮样式，显示 `owner/repository`，悬停可查看完整地址。最近使用的排在最前，同一仓库的大小写、`.git` 后缀和末尾斜杠会归一化去重；网络请求失败也保留地址。API、本地 Git 和项目内云端入口共用记录，应用重启后保留。

点击历史按钮只填入仓库地址，并清空上一个仓库的版本字段与候选列表、聚焦地址框；再点击“查找 skills”才发起查询。历史不记录分支或标签，不保存含凭据或查询参数的地址。

下载开始时，通知固定浮动在窗口顶部，滚动到列表底部或打开弹窗仍然可见。已知文件总数后，进度按实际校验并写入暂存目录的文件计算，同时显示字节和文件名；读取仓库、校验或保存时使用不定进度，不模拟百分比。文件下载 100% 后仍可能需要校验和保存，以最终保存提示为准。

下载和保存绑定解析到的固定 commit，不会在下载中途悄悄跟随分支的新提交。API 只下载选定 skill 及适用的来源许可材料；本地 Git 浅拉取仓库对象，再提取选定目录。两种方式均不执行仓库脚本、包安装或 Git hooks。

“本地 Git”需要先安装 Git 并重新启动 Askills；“检查 Git 安装”会显示检测到的版本。该方式在独立临时裸仓库内执行 `git fetch`，读取原始文件，不执行 checkout、pull 或合并，不改动用户项目仓库。`fetch` 负责获取对象与引用，详见 [Git 官方说明](https://git-scm.com/docs/git-fetch)。后续再次查找会重新获取来源，然后由你选择是否导入和升级项目。

Git 模式沿用本机 Git 的正常系统/用户配置，包括代理与凭据助手；不在 Askills 内保存密码，也不会把 Git 原始错误输出中的敏感信息展示到页面。交互凭据提示关闭，所需凭据应预先配置。输入仍限 GitHub HTTPS 地址或 `owner/repo`，不接受任意 Git 服务、SSH 格式输入或本地路径；本机已有 URL 重写配置可能选择 SSH 传输。无 GitHub API 配额要求；凭据配置理论上可用于有权限的私有仓库，但本轮只验证了公共仓库，没有应用内登录或私有仓库验收。

skill 目录内的许可文件原样保留；位于仓库根部或祖先目录的适用许可证、NOTICE 会保存在快照的 `.askills-source-licenses/` 中，避免覆盖 skill 自己的许可文件。界面出现“许可未声明”时，不应据此推断内容可以自由再分发。

GitHub API 仅支持公开仓库，受 API 配额约束。两种模式都限制选定 skill 的文件数量和大小；过大的目录树、链接文件、子模块、危险路径或不完整引用会报错。Git 模式单条命令最长 120 秒，定期检查临时仓库规模，超过 256 MiB 或条目上限时停止；可取消。候选最多保留 4 份，30 分钟后在下一次操作时清理，退出应用也会释放暂存。网络失败时可检查本机配置或切换另一种方式。本地 skills 库和已登记项目的使用不依赖 GitHub 在线。

在 GitHub skill 详情中点击“检查更新”，会跳转到来源页并带入仓库与 ref。重新查找、下载并确认后，库中可以增加新版本；再按第二节的流程选择需要升级的项目。该按钮不是后台订阅，也不会自动批量升级项目。

页面提供的社区仓库示例是第三方来源，不是 Rust、Tauri 或 Askills 对其内容的官方背书。固定提交、哈希校验和许可记录提供可追溯性，不表示 skill 指令已经通过安全审查。

## 4. 个性化外观

“设置 → 语言与阅读 → 界面语言”可切换“简体中文 / English”；英文入口是“Settings → Language and reading → Interface language”。切换立即生效，退出再启动仍保留，主题设置不受影响。skill 正文与项目/skill 名称保持原文；部分原生诊断会保留原始详情。

“设置 → 个性化”提供 WinUI 风格的界面外观。默认强调色为蓝色，可切换 6 个预设色，或用色盘/`#RRGGBB` 输入自定义颜色后点击“应用自定义颜色”。按钮、选中状态、焦点与进度使用同一套主题色；文字颜色会自动匹配以保持可读性。

外观模式可选“跟随系统 / 浅色 / 深色”。跟随系统会响应系统颜色模式变化；“恢复默认”恢复跟随系统、默认蓝与微软雅黑。设置保存到本地应用数据库，重启后保留。保存失败会提示错误，已应用的主题保持原样。

“界面字体”读取本机已安装的字体，默认微软雅黑。可以搜索字体名称，在下拉框选择后查看预览；界面、表单、路径和代码同步切换，选择自动保存。安装新字体后点击“刷新字体列表”；字体被卸载时自动回退到微软雅黑及系统字体。“恢复默认”也会重置字体。桌面版与 ZTools 插件共用设置，不再内置完整 MiSans 字体文件，离线可用。

这是基于 React/Tauri 实现的 WinUI 视觉风格，仍使用现有应用结构。系统窗口装饰的主题切换取决于平台支持；当前以 Windows 验证为准。

每次启动窗口均居中并使用 1080×720 逻辑像素，不恢复上次的大小或最大化状态。运行期间可以自由调整大小、最大化；系统缩放会改变对应的物理像素数。

## 中断、取消与恢复提示

运行较长操作时可点击“取消操作”。取消会在安全检查点生效；已经进入文件切换阶段的操作可能先完成一致性处理，再返回结果。

Askills 保存安装操作日志，并在桌面应用下次启动时检查未完成的操作：尚未提交的切换尝试恢复原入口，已经提交的操作继续清理自身备份。恢复结果显示在页面顶部。

如果提示“需要处理”，说明遇到未知文件、外部修改、路径不可用或不能确认身份的临时对象。应用会保留这些文件并阻止该项目继续写入。先保留错误信息、检查项目与库是否可访问，保存外部修改后再重新启动；不要通过删除数据库或未知备份来跳过检查。当前没有图形化恢复向导。

本版本也尚未提供应用内 GitHub 登录、其他云端来源、skills 库垃圾回收或应用自动更新。这些功能的规划见 [实现方案](architecture.md)，实际验证范围见 [验证记录](validation.md)。
