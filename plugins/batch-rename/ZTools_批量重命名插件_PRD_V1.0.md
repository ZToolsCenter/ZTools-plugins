# ZTools「批量重命名」插件 PRD

> 文档版本：V1.0  
> 状态：可进入开发  
> 日期：2026-09-25  
> 目标平台：ZTools  
> 首版范围：除「智能重命名」外，其余核心功能全部实现

---

## 1. 项目背景

ZTools 当前已有重命名类能力，但现有方案在「从资源管理器当前选中文件直接进入批量重命名」这一高频场景中，操作步骤偏多。

本项目目标是参考 uTools 官方「批量重命名」插件的优秀使用体验，在 ZTools 中重新实现一套更适合高频文件整理的批量重命名插件。

本项目不是机械复制原插件界面，而是：

1. 保留原插件已经验证过的高效工作流；
2. 第一版完整实现除「智能重命名」外的核心功能；
3. 在不增加用户操作步骤的前提下，对安全性、错误提示、冲突检测等能力进行优化；
4. 尽量使用 ZTools 原生插件能力，与 ZTools 的超级面板 / 文件上下文入口自然集成。

---

## 2. 产品目标

### 2.1 核心目标

用户在 Windows 资源管理器 / macOS Finder 中选中文件后，应能够：

```text
选中文件
→ 呼出 ZTools 文件上下文 / 超级面板
→ 点击「批量重命名」
→ 插件直接打开
→ 当前选中的文件已经自动加载
→ 设置规则
→ 实时预览
→ 一键执行
```

整个流程中，不应要求用户再次手动选择已经选中的文件。

### 2.2 高频功能目标

V1 最高优先级功能：

1. 查找替换
2. 自动编号

同时完整实现：

3. 插入内容
4. 手动编辑
5. 文件导入 / 文件夹递归读取
6. 排序
7. 实时预览
8. 冲突预检
9. 执行重命名
10. 单级撤销

### 2.3 优化原则

> 能比原版做得更好，就做得更好；但不能因为“更安全”而增加明显操作步骤。

允许优化：

- 预览阶段提前发现重名冲突；
- 预览阶段发现非法文件名；
- 失败原因直接显示在文件列表；
- 正常文件继续执行，错误文件自动跳过；
- 支持文件名交换 / 循环重命名；
- 执行前后二次校验；
- 更明确的成功 / 失败汇总。

不做：

- 为安全性增加多余确认弹窗；
- 强制用户先修复所有错误才能执行；
- 为小概率场景设计复杂工作流。

# 4. 用户入口与会话行为

## 4.1 入口 A：文件上下文 / 超级面板

### 场景

用户在资源管理器中选中一批文件。

### 流程

```text
资源管理器选中文件
→ 呼出 ZTools 文件上下文 / 超级面板
→ 点击「批量重命名」
→ ZTools 通过 files 类型 feature 启动插件
→ onPluginEnter 接收文件参数
→ 直接加载选中文件
```

### 行为要求

当插件通过文件入口收到一批新的文件时：

1. 当前文件列表直接替换为新文件；
2. 清除上一任务的单级 Undo；
3. 默认进入「查找替换」；
4. 文件按默认排序显示；
5. 不弹出“是否替换当前任务”确认框。

该入口被视为“明确开始新任务”。

---

## 4.2 入口 B：普通打开插件

触发关键词建议：

- 批量重命名
- 重命名

普通打开时：

- 若插件当前进程内仍保留上一批文件，则继续显示当前任务；
- 不主动读取资源管理器中的当前选中内容，除非 ZTools 宿主在此次启动参数中明确提供文件；
- 不覆盖当前任务；
- 不清空 Undo。

> 开发前必须实测：  
> Windows Explorer 选中文件后，通过 ZTools 主面板快捷键直接搜索「批量重命名」，ZTools 是否会以 files 上下文进入插件。  
> 如果宿主已经自动提供文件，则按入口 A 处理。

# 5. 页面整体结构

## 5.1 顶部功能 Tab

V1 默认顺序：

```text
查找替换 | 自动编号 | 插入内容 | 手动编辑
```

原因：

- 「查找替换」和「自动编号」是最高频功能；
- 提高访问效率；
- 不再保留「智能重命名」Tab。

切换 Tab 时：

- 文件列表保持；
- 当前排序保持；
- 未执行的规则预览立即切换为当前模块的结果；
- 不将不同 Tab 的规则叠加。

> V1 中，每次只使用一个功能模块生成本轮目标文件名。  
> 「查找替换」模块内部允许多条规则串行组合。

---

## 5.2 中间：文件列表

每一行：

```text
[文件图标] 当前文件名    →    [状态] 目标文件名    [移除]
```

建议左右各占约 45%，中间状态 / 箭头占少量空间。

### 状态

#### 绿色

目标文件名与当前文件名一致。

含义：

- 当前规则没有改变该文件；
- 本轮执行时跳过该文件。

#### 橙色

目标文件名合法，且会发生变化。

#### 红色

当前文件存在错误，不能执行。

例如：

- 目标名与同目录另一个目标名重复；
- 目标名已被外部文件占用；
- 文件名为空；
- 文件名包含当前平台非法字符；
- 源文件已经不存在；
- 元数据规则所需信息不存在；
- 其他可预判错误。

红色项必须直接显示可理解的错误原因。

示例：

```text
❌ 与「视频03.mp4」目标名称重复
❌ 目标文件已存在
❌ 文件名包含非法字符：:
❌ 无法读取照片拍摄时间
```

# 6. 文件导入与列表管理

## 6.1 底部左侧按钮

保持原插件成熟布局：

1. 读取文件夹
2. 添加文件
3. 清空

### 读取文件夹

- 打开目录选择器；
- 读取目标文件夹中的文件；
- 默认递归读取所有子目录；
- 不将文件夹本身作为重命名对象；
- 遇到无权限目录时不中断全部扫描，记录并提示。

### 添加文件

- 支持多选；
- 新文件追加到当前文件列表；
- 对完全相同的绝对路径去重。

### 清空

- 清空当前文件列表；
- 清空当前预览；
- 清空当前 Undo。

---

## 6.2 单文件移除

每行右侧提供 `×`。

移除：

- 仅从当前任务中删除；
- 不删除磁盘文件；
- 实时重新计算自动编号与预览。

# 7. 排序

支持以下 8 种排序方式：

1. 按名称升序
2. 按名称降序
3. 按大小升序
4. 按大小降序
5. 按修改时间升序
6. 按修改时间降序
7. 按创建时间升序
8. 按创建时间降序

默认：

```text
按名称升序
```

排序变化后：

- 文件显示顺序立即更新；
- 自动编号立即重新计算；
- 插入序号立即重新计算；
- 文件目标名称实时刷新。

# 8. 功能一：查找替换

## 8.1 普通查找替换

核心输入：

```text
查找 [__________]  →  替换成 [__________]
```

支持：

- 替换指定文本；
- 替换内容为空 = 删除匹配文本。

默认：

- 仅处理主文件名；
- 不处理扩展名。

提供复选框：

```text
□ 替换文件扩展名
```

勾选后：

- 查找范围包括完整文件名与扩展名。

---

## 8.2 特殊查找方式

查找框右侧提供菜单：

1. 前 N 位
2. 后 N 位
3. 从第 X 位开始的 N 位
4. 某字符之后的内容
5. 某字符之前的内容
6. 某字符之后的 N 位
7. 某字符之前的 N 位

### 位置规则

- 所有人类位置输入使用 1-based；
- 默认作用于不含扩展名的主文件名；
- 勾选「替换文件扩展名」后作用于完整文件名。

---

## 8.3 多条替换规则

提供：

```text
+ 添加替换规则
```

支持多条规则。

执行顺序：

```text
规则 1
↓
规则 2 基于规则 1 的结果继续计算
↓
规则 3 基于规则 2 的结果继续计算
...
```

已确认原版行为：串行执行。

例如：

```text
原名：AAA

规则1：A → B
规则2：B → C

最终结果：CCC
```

### 规则操作

V1 必须支持：

- 新增
- 删除
- 按界面从上到下串行执行

若实现成本低，可支持拖动排序；不是 V1 验收阻塞项。

# 9. 功能二：自动编号

## 9.1 参数

界面组成：

```text
[序号前面字符]

[开始序号]
[序号类型]
[固定位数]

[序号后面字符]
```

输出结构：

```text
前缀 + 序号 + 后缀 + 原扩展名
```

例：

```text
前缀：视频_
开始：1
类型：阿拉伯数字
固定位数：3
后缀：_成片

→ 视频_001_成片.mp4
→ 视频_002_成片.mp4
```

---

## 9.2 序号类型

必须支持：

1. 阿拉伯数字
2. 中文小写数字
3. 中文大写数字
4. 英文小写字母
5. 英文大写字母

建议规则：

### 阿拉伯数字

```text
1, 2, 3...
```

固定位数：

```text
001, 002, 003...
```

### 中文小写

```text
一、二、三……十、十一……
```

### 中文大写

```text
壹、贰、叁……拾、拾壹……
```

### 英文小写

```text
a, b, c ... z, aa, ab...
```

### 英文大写

```text
A, B, C ... Z, AA, AB...
```

### 固定位数

V1 中：

- 对阿拉伯数字启用；
- 其他类型禁用 / 隐藏该输入框；
- 避免产生含义不清的“补零字母 / 中文数字”。

---

## 9.3 编号顺序

编号顺序严格基于当前文件排序。

任何排序变化均立即改变编号预览。

# 10. 功能三：插入内容

## 10.1 内容类型

三个子选项：

```text
文本 | 序号 | 文件信息
```

## 10.2 插入位置

三个选项：

```text
开头 | 指定位置 | 末尾
```

说明：

- 开头：主文件名最前方；
- 末尾：扩展名前；
- 指定位置：以主文件名为基准，1-based 位置插入。

默认不修改扩展名。

---

## 10.3 插入固定文本

输入：

```text
固定文本
```

示例：

```text
原名：视频.mp4
文本：最终版_
位置：开头

→ 最终版_视频.mp4
```

---

## 10.4 插入序号

参数沿用自动编号能力：

- 序号前面字符
- 开始序号
- 序号类型
- 固定位数
- 序号后面字符

区别：

自动编号：

```text
直接使用序号内容替换整个主文件名
```

插入序号：

```text
在原文件名指定位置插入序号内容
```

例：

```text
送男朋友1.mp4
送男朋友2.mp4
送男朋友3.mp4
```

---

## 10.5 插入文件信息

V1 支持：

1. 文件创建时间
2. 文件修改时间
3. 文件大小
4. 图片尺寸（宽×高）
5. 照片拍摄时间

允许增加：

```text
[文件信息前面字符] + 文件信息 + [文件信息后面字符]
```

### 默认格式建议

为保证文件名安全：

#### 创建 / 修改 / 拍摄时间

默认：

```text
YYYY-MM-DD_HH-mm-ss
```

#### 文件大小

使用易读格式：

```text
12KB
4.6MB
1.2GB
```

#### 图片尺寸

```text
1920x1080
```

### 元数据缺失

例如普通 PNG 没有 EXIF 拍摄时间：

- 对应文件标红；
- 显示「无法读取照片拍摄时间」；
- 执行时自动跳过该文件；
- 不阻止其他文件执行。

# 11. 功能四：手动编辑

界面：

```text
当前文件名             新文件名
A.mp4                  [____________]
B.mp4                  [____________]
C.mp4                  [____________]
```

支持：

1. 单个编辑目标文件名；
2. 粘贴多行文本；
3. 多行文本按当前列表顺序逐行覆盖。

提示：

```text
粘贴多行文本（如 Excel 复制的一列），将自动向下批量替换
```

## 11.1 多行粘贴规则

例如当前有 4 个文件：

粘贴：

```text
甲
乙
丙
丁
```

对应：

```text
第1行 → 第1个文件
第2行 → 第2个文件
...
```

### 行数少于文件数

- 只覆盖对应的前 N 个文件；
- 剩余文件保持当前名称。

### 行数多于文件数

- 超出行数忽略；
- 给出轻量提示，不弹阻塞确认框。

### 空行

- 空行视为非法目标名；
- 对应项标红；
- 不自动跳过行位移。

# 12. 实时预览与预检

所有规则变化必须实时更新目标文件名。

## 12.1 预检顺序

每次目标名称计算后，对每一项执行：

1. 是否为空；
2. 是否包含平台非法字符；
3. 是否属于 Windows 保留名称；
4. 同目录目标名是否重复；
5. 目标路径是否被“本次任务之外”的现存文件占用；
6. 源文件是否仍存在；
7. 元数据依赖是否满足。

---

## 12.2 同批次文件互换

以下情况不应被错误判定为“外部占用”：

```text
A.txt → B.txt
B.txt → A.txt
```

以及：

```text
A → B
B → C
C → A
```

因为目标文件虽然当前存在，但它同时属于本批次的 source 集合，并会被移动。

这类情况必须允许执行。

# 13. 执行重命名

## 13.1 执行按钮

底部右侧：

```text
▶ 执行重命名
```

即使存在红色错误项，也保持可点击。

点击后：

```text
绿色无变化项 → 跳过
橙色合法项 → 执行
红色错误项 → 自动跳过
```

---

## 13.2 执行前二次校验

预览只是前置检查。

真正执行前必须重新检查：

- 源文件是否仍存在；
- 目标是否突然被其他程序占用；
- 文件权限；
- 父目录是否存在；
- 目标名称是否合法。

文件系统状态可能在预览后变化，因此执行阶段以实际文件系统状态为最终依据。

---

## 13.3 两阶段安全重命名

禁止简单使用：

```text
按列表依次 source → target
```

因为会导致文件交换失败。

必须使用临时名：

### 阶段一

```text
A.txt → .ztools-rename-{uuid}-1.tmp
B.txt → .ztools-rename-{uuid}-2.tmp
```

### 阶段二

```text
temp-1 → B.txt
temp-2 → A.txt
```

临时名称要求：

- 同目录；
- 保证唯一；
- 用户正常不会产生冲突；
- 失败时尽可能恢复；
- 不改变文件内容。

---

## 13.4 部分失败策略

执行采用 best-effort。

例如 100 个文件：

```text
合法：98
错误：2
```

点击执行后：

```text
成功 98
失败 2
```

不能因为 2 个错误阻塞其余 98 个文件。

---

## 13.5 执行结果

成功后顶部 / 右上角显示 Toast：

```text
执行成功：共 98 个
```

存在失败：

```text
重命名完成：成功 98 个，失败 2 个
```

文件列表：

- 成功文件重新基准化；
- 左侧当前文件名更新为新名称；
- 右侧与左侧一致；
- 状态变绿；
- 失败项保留原当前名称；
- 失败项继续标红并显示具体原因。

---

# 14. 单级撤销

## 14.1 基本规则

只支持撤销最近一次“执行重命名”。

例如：

```text
原始名称 → A
A → B
```

撤销一次：

```text
B → A
```

不能继续：

```text
A → 原始名称
```

不做多级 Undo。

---

## 14.2 生命周期

撤销记录：

- 仅保存在当前 ZTools / 插件进程内；
- 关闭插件窗口但 ZTools 没有完全退出：保留；
- 完全退出 ZTools 并重新启动：清除；
- 不写数据库；
- 不持久化。

---

## 14.3 新任务规则

若 FilesCmd / 超级面板传入一批新文件：

```text
清除上一任务 Undo
```

若仅普通再次打开插件：

```text
保留当前任务和 Undo
```

---

## 14.4 撤销执行方式

逐文件 best-effort。

例如有 4 个文件：

- 3 个仍保持执行后的状态；
- 1 个被用户在资源管理器手动改名。

点击撤销：

```text
成功恢复 3 个
失败 1 个
```

Toast：

```text
撤销完成：成功 3 个，失败 1 个
```

失败项显示原因。

---

## 14.5 撤销冲突

如果撤销目标名称已经被其他文件占用：

- 该文件撤销失败；
- 不覆盖现有文件；
- 其他文件继续撤销；
- 最后汇总成功 / 失败数量。

# 16. 错误与异常处理

## 16.1 同一任务内部目标名重复

例如：

```text

B.txt → C.txt
```

预览阶段直接标红。

两项都不执行。

## 16.2 外部文件占用

```text

```

计划：

```text

```

预览：

```text

```

执行时自动跳过。

## 16.3 源文件被删除

预览后文件被删除：

```text

```

其他文件继续执行。

## 16.4 文件无权限

列表显示：

```text

```

## 16.5 Windows 非法名称

预检：

- `<`
- `>`
- `:`
- `"`
- `/`
- `\`
- `|`
- `?`
- `*`

以及保留名称：

- CON
- PRN
- AUX
- NUL
- COM1 ~ COM9
- LPT1 ~ LPT9

同时处理：

- 结尾空格
- 结尾句点

macOS / Linux 根据平台规则校验。

UI 插件通过：

```js

```

接收启动参数。

开发中不要假定 payload 的文件形态。

- FilesCmd；
- 超级面板；
- 普通主面板。

---

## 18.4 preload.js 职责

所有真正文件系统操作放到 preload 层。

包括：

- stat
- 文件 / 目录存在检测
- 元数据读取
- 文件夹递归扫描
- rename
- Undo
- 图片尺寸读取
- EXIF 拍摄时间读取
- 最终二次校验

前端禁止直接暴露完整 `fs`。

仅暴露最小业务 API，例如：

```ts
window.renameService.scanDirectory(...)
window.renameService.readMetadata(...)
window.renameService.validatePlan(...)
window.renameService.executePlan(...)
window.renameService.undo(...)
```

## 18.5 Rename Engine

建议拆成：

```text
Rule Engine
    ↓
Rename Plan
    ↓
Validator
    ↓
Preview
    ↓
Executor
    ↓
Transaction
```

### Rule Engine

纯函数。

输入：

```text
文件 + 当前规则 + 当前排序
```

输出：

```text
目标文件名
```

不操作文件系统。

### Validator

检查：

- 名称合法性
- 重名
- 外部占用
- 元数据错误
- 源文件状态

### Executor

仅负责执行已确认可执行项。

# 19. 性能要求

## 19.1 目标

典型场景：

```text
1 ~ 500 个文件
```

应保证：

- 输入规则时实时预览；
- 页面无明显卡顿；
- 排序响应快速。

压力场景：

```text
1000 ~ 10000 个文件
```

要求：

- 不崩溃；
- 不阻塞主线程数秒；
- 文件扫描 / 元数据读取应分批或异步；
- 超大列表建议使用虚拟列表。

### 注意

图片尺寸 / EXIF 不应在每次普通规则输入时重新读取。

应：

```text
首次需要时读取
→ 缓存到当前会话内
```

不做跨重启持久缓存。

# 25. 技术依据

本 PRD 的 ZTools 接入方案基于官方开发资料：

1. ZTools《快速开始》
   - 插件形态为 Web 前端 + Node.js 本地能力
   - 支持 Vue / React

2. ZTools《AI 插件开发指南》
   - UI 插件使用 `ztools.onPluginEnter`
   - 文件处理插件使用 `files` 类型指令
   - FilesCmd 支持 `minLength` / `maxLength`
   - 文件读写应放在 preload.js
   - 文件类指令默认最多可匹配 10000 个文件

3. ZTools《插件 API 文档》
   - 支持文件选择对话框
   - 支持插件生命周期与入口参数
   - 支持系统能力调用

4. ZTools Native API
   - 支持 Windows / macOS 获取当前选中的文件、文本、图片
   - Windows 使用 UI Automation，并可回退剪贴板方案
   - 支持 Explorer / Finder 中选中的文件

开发阶段以当时安装的 ZTools 最新稳定版实际行为为最终准则。
