# SAZ 抓包解析（saz-parser）

把 Fiddler 的 `.saz` 抓包归档转换成**可以直接交给 AI 分析的结构化素材**，同时保留与原 Python 解析脚本同构的目录树导出。

纯本地运行：**零第三方依赖、不联网、不调用任何模型**。隐私字段（Cookie / Authorization / token / 设备标识 / 签名）**默认完整保留**——它们就是分析对象；脱敏只是可选的副本导出，绝不静默抹除。

---

## 它解决什么问题

| 痛点 | 本插件的做法 |
|---|---|
| 全量解析出来的平铺目录约 **97 万 token**，AI 一口吃不下 | L0–L3 四档详细度 + 单卷 token 预算（默认 100,000）+ 自动分卷，超预算按优先级降级并输出**被裁清单**（`trimLog`），每条都能回溯到原始 `bodyRef` |
| 原脚本丢弃 WebSocket 帧日志（`raw/<sid>_w.txt`） | 按 Fiddler 帧日志的字节格式逐帧解析，再按 RFC 6455 解 opcode/掩码/长度；实测取回 **34 会话 / 1984 帧 / 1007KB** 原本完全丢失的业务数据 |
| `Transfer-Encoding: chunked` 的分块框架没剥，导致正文混着长度行、甚至**压缩流必然解压失败** | 按 RFC 9112 先做 transfer-decoding 再解压；实测影响 **245 条**会话，其中 209 条原本正文整条不可用 |
| SSE / 多帧 JSON 正文被整块当 JSON 解析失败，AI 拿到一坨未拆分文本 | 逐事件拆分并结构化每个 `data`；实测 19 会话 / **5030 事件** / 5023 个 `data` 为合法 JSON |
| 手工按域名翻几千条会话 | 秒级索引（3756 条约 1–3s，不解正文）+ 域名/端点归并 + 业务流程分组 + **跨会话参数传递链**（A 响应的 token 出现在 B 请求） |
| 只能靠鼠标一条条点 | 条件对象取数（ domains / urlRegex / methods / status / contentType / transferEncoding / hasAuth / bodyContains / flow / sidRange ），三个入口（UI 高级筛选 / 配置文件 / MCP 工具入参）产出**完全一致**的 selection |

## 安装

- **插件中心**（推荐）：等本插件进入 ZTools 插件中心后直接安装。
- **手动导入**：「导入插件」只接受**压缩包**，不接受目录；把本目录压成 zip（plugin.json 必须在压缩包根）后选择它。
- **开发态**：把本目录整体拷进 `<插件目录>/saz-parser` 即可加载——本目录就是安装后的 1:1 内容，`preload/` 是未打包、未压缩的 CommonJS 源码，可直接阅读与断点。

要求：ZTools 3.x。解压/gzip/brotli/zstd 走宿主内嵌 Node 的 `zlib` 原生能力，插件在运行时做特性检测（旧客户端缺 zstd 时会在诊断页明示，不会静默丢数据）。**运行时零第三方依赖**，装完不需要 `npm install`。

## 使用

**两条入口，用途不同：**

- **粘贴 / 拖入 / 输入 `.saz` 路径** → 出现两条候选：
  - `一键解析`：**不开界面**，直接在归档旁生成与原脚本同构的目录树（`<归档名>_解析结果`）。
  - `SAZ 分析`：打开界面做索引、筛选、分析包生成。
- **搜索框输入 `SAZ 抓包解析`** → 只有一条：打开界面。

产物默认落在**归档所在目录**下：分析包 `<归档名>_分析包`、兼容层 `<归档名>_解析结果`。

**推荐流程**：先出 L0/L1 让 AI 读全局 → AI 告诉你要看哪几个域/流程 → 用条件对象回选 → 生成 L2（每卷 ≤100K token）→ 把 `00-OVERVIEW.md` + 对应卷交给 AI；要追某一条报文的具体字节时再按 `bodyRef` 取 L3。

```
├── 50-sessions.md        会话清单（一行一条）

```

## MCP 工具（5 个）

需要客户端支持插件声明 `tools`；不支持时，同一套能力仍可通过分析包文件与条件对象使用（功能不打折）。

| 工具 | 作用 | 说明 |
|---|---|---|
| `saz_parse` | 索引 + 概览 | 只读头部，秒级；默认返回前 200 行会话 |
| `saz_query` | 条件取数 | 含传输层维度：`chunkedOnly` / `eventStreamOnly` / `transferEncoding[]` |
| `saz_body` | 取已解码正文 | 隐私值原样返回；附带 dechunk 留痕 |
| `saz_ws` | 取 WebSocket 帧 | 逐帧方向/时间/长度/载荷 |
| `saz_stream` | 取事件流/多帧正文 | 按 `sid` 分页取事件与顶层多值 |

**插件自身不调用任何模型**：AI 侧只做"给数据"，不替你思考，也不上传任何内容。

## 数据保真原则

- 任何裁剪、截断、降级都必须留痕（`trimLog` / 异常清单 / `manifest.json`），**禁止静默丢数据**。
- 与原 Python 脚本的产出不一致处，全部登记在导出清单的"有意不一致"里（共 8 条，逐条说明原因）。
- 与算法基线做过逐目录对拍：请求/响应头等价、JSON 正文语义等价、正文差异 100% 可归因（换行改写 / 美化器重排），并有"落盘字节 == 归档解码明文"的绝对不变量断言。

## 本目录的内容

| 路径 | 是什么 |
|---|---|
| `plugin.json` | 插件清单：2 个功能入口 + 5 个 MCP 工具的 schema |
| `index.html` + `assets/` | 界面（vite 构建产物） |
| `preload/` | 运行时全部逻辑：**未打包、未混淆的 CommonJS 源码**（ZIP 中央目录解析、transfer-decoding、解压、拆帧、KV 树、分析包、兼容层导出都在这里） |
| `docs/` | 设计与开发文档（取证版已脱敏：归档名→`样本-NN`、域名→`域名-NN`、本机路径→占位符；**所有实测数字原样保留**） |
| `images/` | 界面截图。均由**开发态假数据**（`*.example.com`、`DEV 事件`）截得，里面没有一条真实报文 |

验证与构建工具链（5 条验收线共 384 条断言、各类实测探针、发布合规扫描器）在开发工作区维护，不随本发布包分发；
上面列出的每一个数字都由那些脚本在真实归档上跑出，不接受"预期提升"式描述。

```bash
npm install          # 仅开发依赖（vite / vue / typescript），运行时零依赖
npm run dev          # 浏览器开发态（内置假数据桩，不接触真实抓包）
npm test             # 五条验收线：引擎 74 + 分析包 56 + 兼容层对拍 24 + preload/工具 210 + 装配 20
npm run typecheck    # vue-tsc
npm run build        # 构建 + 装配自检 + 发布合规扫描 + 直接替换本机已安装插件
```

## 已知限制

- 无 `.proto` 时 protobuf 正文只保留原始字节（子协议名已记录在会话字段）。
- JS 正文**有意不做重排美化**：朴素重排会破坏模板串/正则/ASI 语义，属"改坏比不改更糟"。
- 事件流 `data:` 内的 JSON 默认不展开缩进（展开会改变重放时的字符串），需显式开启。
- 单次触发处理一个归档；多归档切换、HAR 1.2 导出在路线图上。
- 分析包是否"AI 真的用得好"属于外部实验，本插件只保证离线指标（体积、可回溯、字节保真）。
