# 变量命名工具设计

## 背景

研发助手当前提供 JSON、Base64、URL、时间戳、返回值解压、二维码、计算器、日历、Crontab、UUID 等工具。新增能力命名为 `变量命名`，用于把中文或自然语言描述转换为适合代码使用的英文变量名。

## 目标

- 用户可以在插件内填写百度翻译 API 配置。
- 用户输入中文或自然语言短语后，工具调用百度翻译得到英文表达。
- 工具根据英文表达生成多种变量命名格式。
- 生成结果可以像现有工具结果一样一键复制。

## 非目标

- 不把百度翻译 App ID 或密钥写死到源码、`plugin.json` 或构建产物中。
- 不新增复杂账号系统或远端配置同步。
- 不改变现有 JSON、Base64、URL 等工具行为。

## 用户流程

1. 用户打开研发助手，选择 `变量命名`。
2. 用户填写百度翻译 App ID 和密钥，并保存到本机。
3. 用户输入中文或短语，例如 `用户订单金额`。
4. 用户点击生成，工具调用百度翻译得到英文词组。
5. 工具清洗英文词组并输出多种命名格式。
6. 用户点击某一行结果的复制按钮。

## 命名格式

首版支持以下格式：

- `camelCase`：例如 `userOrderAmount`
- `snake_case`：例如 `user_order_amount`
- `PascalCase`：例如 `UserOrderAmount`
- `kebab-case`：例如 `user-order-amount`
- `CONSTANT_CASE`：例如 `USER_ORDER_AMOUNT`

英文清洗规则：

- 统一转小写后拆分单词。
- 移除标点、括号、引号等不适合变量名的字符。
- 连续空白、下划线、短横线都视为分隔符。
- 结果为空时返回错误，不生成空变量名。

## 架构

### `public/preload/services.js`

新增百度翻译调用能力：

- 接收 `query`、`appId`、`secretKey`。
- 在 Node 侧生成百度翻译签名，避免在前端拼接敏感逻辑。
- 使用 HTTPS 请求百度翻译通用翻译接口。
- 返回翻译后的英文文本或结构化错误。

### `src/DevTools/tools.js`

新增工具定义：

- `id`: `variable-naming`
- `name`: `变量命名`
- `description`: `中文短语转代码变量名`
- `placeholder`: `输入中文或短语，例如：用户订单金额`

新增纯函数：

- 英文文本清洗。
- 单词拆分。
- 多命名格式生成。

这些纯函数不依赖网络，便于独立验证。

### `src/DevTools/index.jsx`

新增 `变量命名` 的特殊 UI 分支：

- 输入框复用现有工具输入体验。
- 配置区包含百度翻译 App ID、密钥、保存按钮。
- 生成按钮触发异步翻译和命名转换。
- 结果区复用现有 `{ id, label, value }` 结果结构和复制按钮。

### `public/plugin.json`

补充功能指令时继续遵守 uTools 建议：每个功能的 `cmds` 不超过 5 个。

推荐调整 `dev-tools` 指令为：

- `研发工具`
- `研发助手`
- `变量命名`
- `json`
- 一个 `over` 类型文本处理入口

## 配置存储

优先使用 uTools 本地数据库能力保存配置；如果当前运行环境没有 uTools DB，则回退到 `localStorage`。

保存内容：

- 百度翻译 App ID
- 百度翻译密钥

配置只保存在用户本机，不进入源码和构建产物。

## 错误处理

- 未填写 App ID 或密钥：提示 `请先填写百度翻译 App ID 和密钥`。
- 百度翻译接口返回错误：展示接口错误码或错误信息。
- 网络失败：提示 `百度翻译请求失败，请检查网络或 API 配置`。
- 翻译结果为空：提示 `未得到有效英文结果`。
- 命名结果为空：提示 `无法从翻译结果生成变量名`。

## 测试与验证

实现完成后需要验证：

- `npm run build` 成功。
- 未配置 API 时显示明确错误。
- 输入 `用户订单金额` 时可以生成多种命名格式。
- 命名转换纯函数覆盖中文翻译后的英文短语、带标点文本、下划线文本、短横线文本。
- `public/plugin.json` 和 `dist/plugin.json` 中每个 feature 的 `cmds` 数量不超过 5。
- `dist/index.html`、`dist/plugin.json`、`dist/logo.png` 仍存在，满足 uTools 打包入口要求。
