01

问题判断

你现在看到的不是“选中背景和面板背景差不多”，而是选中样式被关掉了。

updateRow 会把主行 background 强制写成 transparent，并把 boxShadow 写成 none。CSS 只给 hover 行铺底，选中行只靠显示 PID 提示位置。

浅色面板底是 #fafafa，行默认也是透明，所以截图里 Dia / ChatGPT / 企业微信几乎看不出当前行。

好消息是 token 已经准备好了：浅色 --bg-row-sel=#e8e8e8、--bg-row-hover=#f1f1f1；深色 --bg-row-sel=#202020、--bg-row-hover=#151515。重构时优先复用黑白体系，不引入彩色。

02

三方案对比

三方案对比
方案视觉优势风险适合场景
A. 轻底 + 左线（推荐）当前组浅灰底 + 2px 左线；hover 弱于 selected；展开 helper 与主行同底位置一眼可见；符合任务管理器/Finder 习惯；黑白极简比纯文字稍重一点常用用户、键盘快速定位、默认落地
B. 仅左线 + 名称加粗无整行底；2px 左线；名称 450→600；PID 常显最干净；对一屏密度影响最小快速扫列表时仍可能不够醒目极度克制、讨厌色块
C. 整组卡片块当前组圆角卡片 + 细边框；helper 包进同一卡片分组结构最清楚；结束前最不容易点错组视觉最重；长列表会有块状感强调按应用分组结束

03

建议 token / 样式规则

建议 token / 样式规则
状态浅色深色规则
默认行透明透明保持高密度表格感
hover#f1f1f1#151515只作用于未选中行；弱于 selected
selected 组底 #e8e8e8 + 左线 #171717底 #202020 + 左线 #f5f5f5主行与展开 helper 共用；方案 A 默认
selected 文本名称可保持 450 或轻提到 500同左方案 B 才强制 600，避免 A/C 过重
PID 提示selected / hover / focus-within 显示同左保留现有轻量定位，不单独承担选中识别

06

推荐结论

默认落地方案 A：轻底 + 左线。

原因：你当前最大痛点是看不见选中；A 能立刻解决，同时仍保持黑白极简，不会把列表做成彩色工具栏。

方案 B 作为备选：如果你确认讨厌任何行底色，再降到“线 + 字重”。

方案 C 不建议默认：分组感最强，但对这款高密度进程表偏重。

落地时同步改 dense-list-style 测试，把“禁止背景/左线”改成“必须有可见 selected 样式，且 hover 弱于 selected”。
