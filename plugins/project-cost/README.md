# 项目费用管理 · ZTools 插件

把原先的单文件网页台账（`renovation-cost-manager.html`）移植为 ZTools 插件，并按启动器窄窗口（`800 × ~620`）重新设计了版式与交互。

> **v1.1 更名**：原「装修费用管理」更名为「项目费用管理」，定位从单一住宅装修扩展到任何按项目记账的费用台账（装修、门店改造、工程分包等）。插件标识 `project-cost`，命令词保留「装修费用」「装修」等旧关键词，搜索习惯不变；本地数据自动从旧键 `ztools_renovation_cost_v1` 迁移到 `ztools_project_cost_v1`，无需手动导入。

## 为什么重做版面

原版是 1200px 宽的「管理后台」：六页签 + 12 列宽表格 + 5 个居中弹窗。ZTools 插件窗口宽度固定 800px，直接塞进去会横向溢出、弹窗遮满屏、切页丢上下文。因此器件按「启动器原生」重排：

| 维度 | 网页版 | 插件版 |
| --- | --- | --- |
| 导航 | 顶部六页签，占两行 | 左侧 62px 图标轨道，一屏常驻 |
| 支出列表 | 12 列宽表格 + 横向滚动 | 两行式条目流（主信息 + 品类/对象/日期），金额右对齐 |
| 详情 | 居中弹窗遮全屏 | 右侧 392px 抽屉，背后列表保留上下文 |
| 明细/付款 | 各自独立弹窗，与支出弹窗割裂 | 同一抽屉内分段就地增删，不用来回开关 |
| 筛选 | 工具栏堆 5 个控件 | 命令条：搜索 + 状态段 + 品类 + 排序 + 日期折叠 |
| 主题 | 固定浅色 | 跟随 ZTools 深/浅色，可手动切换 |
| 键盘 | 全局快捷键 + G 序列 | `⌘K` 搜索、`J/K` 移动、`Enter` 打开、`1–6` 分区、`Esc` 关闭 |
| 入口 | 只能打开页面 | 三个 feature：主入口 / 记一笔 / 付款跟踪，直达动作 |

## 功能

- **多项目**：每个项目独立预算 / 品类 / 支付对象 / 支出 / 付款，可重命名、切换、删除，可存为模板复用。
- **明细驱动金额链**（唯一真源）：明细金额合计 → 项目总计 → 应付（总计 − 优惠）→ 已付（Σ付款）→ 待付。有明细时总计自动汇总并锁定只读；数量 × 单价齐全时金额自动算并锁定。
- **付款跟踪**：逐笔流水（支持负数退款），每笔有稳定编号与备注/凭证号，超付软确认，逾期 / 临期（≤7 天）提醒；记错了可**作废留痕**（不计入已付、可恢复），也可**批量登记**多笔。
- **预算预警**：品类预算进度、超支与临界（默认 80%）提示，顶栏横幅按类型收敛，不撑爆窄窗口。
- **分析**：品类结构、预算 vs 实际、收款方账目占比、欠款排行、付款月度趋势、费用类型构成。
- **导出**：Excel（支出 / 明细 / 付款三表，数值列按数字写入）、CSV、全量 CSV、JSON 备份；JSON 可再导入还原。
- **数据搬家**：网页版导出 JSON → 插件内「导入 JSON」。插件使用独立存储键 `ztools_project_cost_v1`（从 1.0 版键名自动迁移），不会与网页版互相覆盖。

### v1.2 新增（Q1 / Q2 / C1 / R2 / B2 / X3）

- **Q1 自动快照与一键回滚**：每天首次启动自动存一份快照（含导入 / 清空 / 恢复默认 / 体检修复 / 回滚前的强制快照），设置页「历史版本」可一键回滚；保留 7 份日快照 + 3 份操作前快照，总量上限 1.5MB，快照存在独立键 `ztools_project_cost_snap_v1`，**不参与主数据保存链路，写失败也不影响账目**。快照不含凭证图。
- **Q2 数据体检与一键修复**：9 类数据问题（未填品类、品类/收款方档案缺失、明细合计≠总计、付款无日期、付款超应付、项目号重复、预算对应品类已删除、预算合计字段不一致），6 类可一键修复；**所有修复动作都不改变应付/已付/待付**，文案明示「金额未变动」。缺日期的付款只提示不代填，避免伪造对账事实。
- **C1 付款流水补全**：付款记录新增「备注」「凭证号」，导出付款表增至 8 列（前 6 列不变）；新增付款日期必填，历史无日期记录允许保留空值并高亮提示，不会被悄悄补成今天。
- **R2 明细连续录入**：明细表单加「保存并继续」——保存后清空品名/数量/单价/金额、保留单位与预估标记、焦点回到品名框，可一口气录完一张报价单；表单顶部实时显示「本项已有 N 条 · 合计 · 项目总计」。
- **B2 抽屉内实时预算剩余**：编辑支出时选完品类、填好金额即提示「该品类预算剩余 X，本笔后剩 Y / 将超支 Z」，口径与预算页一致（应付 = 总计 − 优惠），编辑既有费用项时排除自身。
- **X3 按当前筛选导出**：支出列表右侧「导出 / 导出筛选」按当前状态、品类、关键词、日期区间导出，支出表 / 明细表 / 付款表共用同一作用域，三表行数必然一致；无筛选时导出全量。

### v1.3 新增（R1 / R3 / R4 / R5 / B1 / C2 / C3 / X1）

- **R1 明细批量粘贴**：明细态加「批量粘贴」——粘贴 TSV/CSV（品名/单位/数量/单价…）→ 解析预览 → 一次落库多条；金额 = 数量 × 单价自动算，坏行剔除不入库。
- **R3 品名历史单价联想**：品名输入带 datalist，按历史明细构建内存索引提示「单位 / 最近单价」，采纳后自动填单位与单价。
- **R4 费用项复制（含明细 / 跨项目）**：详情页「复制到…」可复制到当前或其他项目，明细一并复制、编号按目标项目顺延；**付款不复制**（避免虚增已付）。
- **R5 列表多选与批量操作**：费用列表加多选（Shift 连选）+ 底部批量条（改品类 / 改收款方 / 改到期日 / 删除）；删除走 5 秒撤销；不破坏 J/K / Enter / ⌘K 与滚动。
- **B1 预估与应付分离（双口径）**：新增派生「确定应付 = 应付 − 预估合计」，预算占用率与超支/临界预警改按确定应付算；真源「应付 / 待付」保持不变（待付仍为全口径）。
- **C2 重复付款 / 重复费用项检测**：付款保存前校验「同费用项 + 同日期 + 同金额」，费用项保存前校验「同收款方 + 同金额 + 同备注」，命中弹二次确认，编辑既有记录排除自身。
- **C3 收款方对账单**：按收款方生成对账单（费用项金额 / 已付 / 待付 + 付款流水 + 三行小计），支持打印（A4 专用 CSS，三级降级）与导出 CSV。
- **X1 CSV 导入（三表回读）**：设置页「导入」支持费用项 / 明细 / 付款三表 CSV，按表头对齐列、冲突策略（追加 / 按编号覆盖 / 跳过已存在），**落库前自动存快照**可回滚。

> 升级提示：v1.3.0 为纯增量，无破坏性结构变更，沿用主键 `ztools_project_cost_v1`；升级后金额链真源三项（应付 246,055.97 / 已付 188,529.11 / 待付 57,526.86）字面不变，新增「确定应付 231,180.97 / 其中预估 14,875.00」两个派生展示值。

> 已知限制（**v1.6 已修**）：同日多笔付款时「只拿其中一行」做覆盖导入会按位置命中第 1 笔 —— 已由付款唯一键 `付款编号` 解决；R1 预览表未提供行删除键（坏行已列出且不落库）。

- **A1 账龄分桶**：分析页新增「账龄」页签，按到期日（未填则下单日 + 30 天）把待付分成 **0–30 / 31–60 / 61–90 / 90 天以上** 四桶，显示金额与笔数；点桶展开该桶费用项（逾期天数 + 收款方，点行直接开抽屉），右上角下拉可按收款方下钻。四桶金额之和恒等于待付合计，未到期的欠款归入 0–30 桶。

### v1.5 新增（M3 / M2 / M1 / A2 / A3 / A4）

- **M3 到期日推算可配**：设置页「到期日推算」按项目设 1–365 天（默认 30）。只影响**未填到期日**的费用项（下单日 + N 天），已填到期日的不受影响；逾期判断、账龄分桶、临期提醒、对账单到期日全部改用同一口径。7 天结的工长填 7、月结 45 天填 45，不再被"一律 30 天"误判。
- **M2 逾期分级**：逾期拆成**逾期 1–30 天**与**超 30 天**两档。付款页顶部新增「超 30 天 · 优先催收」置顶卡（天数徽标 + 品名 + 金额 + 收款方，点行开抽屉），按逾期天数降序；顶部预警里超 30 天的 chip 用**实心 danger** 与前两档区分，超过 8 条汇总时单独给出「超30天 N 笔」。
- **M1 预警忽略按天持久化**：点「忽略」后当天该类提醒不再出现在横幅里，**跨天自动恢复**，**左轨角标仍保留计数**（不会因为忽略而变成无预警假象）；设置页「预算临界预警」下方显示「今日已忽略 N 类提醒」并提供一键「恢复」。忽略状态存独立键 `ztools_alert_ignore_v1`，不进主数据、不进快照。
- **A2 材料（明细品名）支出排行**：分析页新增「材料」页签，按**明细品名**合并（忽略空格与大小写）排 Top10，显示占比条 / 金额 / 条数，点行直接打开该品名金额最大的费用项。**可对账**：Top 合计 ＋ 其他 N 种 ＝ 明细合计（247,577.89），与费用项明细逐分一致。
- **A3 月度环比**：分析页「费用构成」顶部新增「本月 vs 上月」三格 —— 应付 / 已付 / 新增费用项各自的增减与百分比（应付按**下单日期**归月、已付按**付款日期**归月），并给出「变化最大的品类」。
- **A4 单方造价（元/㎡）**：项目管理抽屉可为每个项目填建筑面积；填了才在概览「预算执行」与分析页命令栏显示 `¥X,XXX/㎡`（应付 ÷ 面积）。未填则整项隐藏，绝不显示「¥0/㎡」误导。面积只参与这一项指标，不进入任何金额链。

> 已知限制（**付款唯一键部分已在 v1.6 解决**）：R1 批量粘贴预览表无行删除键（坏行已列出且不落库）。

### v1.6 新增（K1 / C5 / C4）

- **K1 付款唯一键**：每笔付款在项目内获得稳定编号 `P0001`（导出付款表新增末列「付款编号」）。**修掉一个会算错账的缺陷** —— 同一项目同一天有多笔付款时，只拿其中一行做「按编号覆盖」导入会永远命中第 1 笔（已付悄悄虚增）；现在按编号精确定位，改哪笔就是哪笔。顺带修掉「导出→导回每次丢 6 笔无日期付款」（有编号的行允许日期留空）。
- **C5 付款作废留痕**：付款行加「作废 / 恢复」——**作废 ≠ 删除**，记录灰显留在流水里、保留编号与凭证号，只是不再计入已付（可随时恢复）；真正要抹掉才用「× 彻底删除」。作废款不进环比、趋势、体检与对账单，也不会被导出→导回「复活」（付款表新增末列「作废」）。
- **C4 批量登记付款**：费用列表勾选多条 →「批量付款」，输入总额并按**待付比例**或**均分**自动拆行，最后一行吸收分角差（Σ 恒等于总额），面板内逐笔预览后一次落库，整批一次撤销。

> 升级提示：v1.6.0 沿用主键 `ztools_project_cost_v1`；付款记录新增 `pid` / `void` 两个字段，老数据打开自动补齐（合法编号保留、缺失或重复才补发，**不重排不丢号**）。付款表列数 8 → 10（前 8 列逐字不变），旧的 8 列文件仍可导入。金额链真源三项（应付 246,055.97 / 已付 188,529.11 / 待付 57,526.86）与 B1 派生（231,180.97 / 14,875.00）字面不变。


## 开发与打包

```bash
npm install          # 首次
npm run dev          # 浏览器预览（建议窗口 800×620）
npm run build        # 产出 dist/
npm run package      # 产出 releases/*.zip / *.zpx / *.asar
python3 generate_logo.py   # 重新生成 logo.png
```

安装：ZTools → 插件管理 → 安装本地插件，选择 `releases/project-cost-<version>.zpx`；或把 `dist/` + `plugin.json` + `preload.js` + `logo.png` 放进 `~/.ztools/plugins/project-cost/`。

## 默认台账校验

首次进入预置一份真实装修台账作为示例（可随时清空或另建项目），可核对：应付 `246,055.97`、已付 `188,529.11`、待付 `57,526.86`、预算 `234,688.00`、结余 `-11,367.97`。

> v1.2 提示：默认台账里有 6 笔历史付款没填日期（合计 `4,142.00`），所以「数据体检」会报 1 类提示、0 类可修复——这是诚实的结果（不改日期以免伪造对账事实），不是缺陷。

## 自验脚本

**一键跑全部（推荐）**：`node scripts/verify-all.mjs`（12 套件，含 2 套 headless UI 冒烟，约 1 分钟）；
也可只跑指定套件，如 `node scripts/verify-all.mjs v16 v16ui`。

单跑时按 ESM 写成，`src/lib/*` 里的相对导入没有省略扩展名，node 直接跑不通，
用 esbuild 打成单文件后执行：

```bash
npx esbuild scripts/verify-t01.mjs --bundle --platform=node --format=esm --outfile=/tmp/t01.mjs && node /tmp/t01.mjs
npx esbuild scripts/verify-t02.mjs --bundle --platform=node --format=esm --define:process.env.NODE_ENV='"development"' --outfile=/tmp/t02.mjs && node /tmp/t02.mjs
npx esbuild scripts/verify-t05.mjs --bundle --platform=node --format=esm --outfile=/tmp/t05.mjs && node /tmp/t05.mjs
```

- `verify-t01`：金额链基线（71 / 384 / 88 / 246,055.97 …）、`checkup` 纯函数与基线、`catBudgetHint` 口径、`pruneTo`、`filters`
- `verify-t02`：快照冷启动/去重/淘汰、导入前快照、回滚、付款日期必填与备注凭证号、`setBudget` 同步、`fixCheckup` 金额零变化
- `verify-t05`：导出三表一致性、付款表 10 列、文件名摘要（会产出 `/tmp/t05-*.xlsx` 供 unzip 校验）
- `verify-v16`：K1 付款唯一键（发号/回填/导出列契约/同日多笔精确覆盖/无编号文件向后兼容）、C5 作废（金额增减、幂等、不被重复检测挡住、往返不复活）、C4 批量付款（比例/均分/余数收敛/超付/一次撤销）
- `verify-v16-ui`：headless 冒烟 —— 抽屉作废→灰显→恢复、彻底删除、批量付款面板预填与落库、编号唯一性体检
