## 2. A1 账龄分桶

### 2.1 口径定义（唯一真源不变）

- **账龄** = `today − effectiveDue(p)`；`effectiveDue` 沿用 v1.1 起的规则：**优先「到期日」，未填则「下单日 + 30 天」**。
- **只统计欠款**：`dueOf(p) > 0.005`（`dueOf = payableOf − paidOf`，仍是全口径，与 v1.3 的 B1 决策一致）。
- **未到期（账龄 ≤ 0）归入 0–30 桶**，因此 **四桶金额之和恒等于待付合计**（验收硬断言）。
- **多付项（due < 0）不参与分桶**：分桶不做负数相抵。基线台账无多付项，故 `Σbuckets.amount === stats.remain` 字面成立（由 `verify-v14` 断言守护）。
- **收款方字段用 `project.object`**（不是 `payee`）——与 `calc().byPayee`、导出「收款方」列同源。这是本次实现中唯一踩到的字段歧义，已写入注释。

### 2.2 接口（`src/lib/core.js`）

```js
export const AGE_BUCKETS = [
  { key: 'b0', label: '0–30 天', min: 0, max: 30 },
  { key: 'b1', label: '31–60 天', min: 31, max: 60 },
  { key: 'b2', label: '61–90 天', min: 61, max: 90 },
  { key: 'b3', label: '90 天以上', min: 91, max: Infinity },
];

agingRows(book, today?, payee?) →
  { buckets:[{key,label,amount,count}], items:[{id,no,name,payee,due,overdue,amount,bucket}],
    total, maxDays, worst, payees, payee, today }

agingPayees(book, today?) → [{ name, owe, count, maxDays }]   // 仅仍有欠款的对象，按欠款降序
```

零副作用：不 mutate 入参，不写任何 store 字段（`verify-v14` 断言调用前后金额链零变化）。

## 3. Q3 存储占用与配额预警

### 3.1 计量模块（`src/lib/storage.js`，新建，只读）

- **口径**：localStorage 以 UTF-16 计，`(key.length + value.length) × 2` 字节 —— 与 Chromium 触发 `QuotaExceededError` 的口径一致。
- **弃用 `navigator.storage.estimate()`**：`file://` 的 webview 里常返回 0 或抛错，不可作为分母。
- **分母**：`QUOTA_BYTES = 5 MB`（展示用常量，不改真实配额）。
- **分类**：`main`（主键 + 网页版历史键）/ `snap`（`*_snap*` 快照键）/ `other`（主题等杂项），三者之和 = `bytes`。
- **分级**：`< 80% ok` / `≥ 80% warn` / `≥ 100% over`；`percent` 保留一位小数。
- **永不 throw**：环境禁用 localStorage 时返回 `{ ok:false, text:'不可用' }`。

```js
storageUsage(quota?) → { ok, bytes, quota, ratio, percent, level, main, snap, other, keys, keyCount, text }
fmtKB(bytes) / usageLevel(ratio) / byteLen(str) / QUOTA_BYTES / WARN_RATIO
```

### 3.2 写入失败可见（`src/lib/store.js` + `src/App.vue`）

问题根因：v1.3 及以前的 `lastError` **只写不读**——配额满静默删凭证图后用户毫无感知（需求池 Q3 原话）。

- 新增 `export const saveErr = ref('')` 与 `takeSaveErr()`；`persistNow()` 在三种情况下赋值：
  1. 配额满 + 删图成功降级 → `本地存储已满，已自动移除 N 张收据图片以保全数据`
  2. 配额满 + 删图仍失败 → `本地存储已满，请先导出备份再继续录入`
  3. 其它异常 → `保存失败：<原因>`
- **成功不清空**：避免「失败后紧跟一次成功」把提示吃掉；只由 `takeSaveErr()` 消费。
- `App.vue` 用 `watch(saveErr)` → `toast(takeSaveErr(), { duration: 4600 })`；`ui.toast` 因此新增 `opts.duration`（不污染 `undo` 语义）。

## 5. 已知限制

1. 账龄按**费用项**粒度算，不按「部分付款」分摊 —— 一笔费用项付了一半，整条按剩余金额落桶（与「待付」同粒度，不做 FIFO 冲抵）。
2. 多付项（`due < 0`）不计入任何桶，因此 `Σbuckets` 在**存在多付项**的台账上会略大于 `stats.remain`；基线无此情况，UI 无特殊提示（若要严格相等需在桶外用「多付」一行对冲，留后续）。
3. 占用分母 5 MB 为展示常量，真实配额随宿主 webview 变化，`≥ 100%` 文案属保守提示。
4. 同日多笔付款「只覆盖其中一行」的位置歧义（v1.3 遗留）本批未处理。
