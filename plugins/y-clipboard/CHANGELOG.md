## 1.0.19 - 2026-10-09

- **新增：链接记录可直接用浏览器打开**（链接行的操作区多了"外链"按钮）
  - 按钮**按内容判定**（`webUrlOf(content)` 能解析出网址才渲染），不是按宿主分类 ——
    同一段 URL 被归成"文本"时也照样有入口；普通文本、代码、颜色值上不会出现。
  - 只放行 **http / https**：`file://`、`data:`、`javascript:` 一律拒绝

    裸 `www.` 或裸域名自动补 `https://`。
  - 走宿主官方 `shellOpenExternal`，缺失时退回 `window.open`（开发模式/老宿主）；
    打开成功后**自动退出插件** —— 和"定位文件"同一个坑：浏览器窗口会开在
    置顶的插件窗口后面，不退出用户会以为点了没反应。
- 新增第 11 套回归测试 `design/check-link.mts`（**39 项**）：网址规范化边界
  （补协议 / 拒绝 file:、data:、javascript:、散文、颜色值）+ 界面契约

  成功后退出窗口）。全部 11 套 **521 项**通过。

## 1.0.18 - 2026-10-09

- **修复：点五角星收藏后星不点亮**（收藏能记住、计数也涨，就是图标不变色）
  - 根因是"两套 id 混用"：收藏以**内容 key**（`favKey` = `djb2(kind+content)`）持久化，
    而列表记录的 `id` 是宿主给的历史 id。旧代码在 `App.vue` 造的是收藏 key 的集合，
    到 `VirtualList` 却拿 `row.rec.id` 去查 —— 永远查不中。只有"收藏"分类下
    记录的 id 恰好被赋成了收藏 key，才碰巧点亮，其余分类全不亮。
  - 修法：`VirtualList` 的 `starredIds: Set<string>` 改为判定函数
    `isStarred(r) => boolean`，由 `App.vue` 统一用 `favKey(r)` 查表（O(1)，且
    远端搜索结果一并覆盖）。同一条内容的多条历史记录会一起点亮（收藏本就是按内容算的）。
- 新增第 10 套回归测试 `design/check-star.mts`（**25 项**）：既锁行为
  （点谁谁亮、同内容都亮、再点熄灭、收藏分类下可点、写入持久化），也锁源码契约
  （不许再出现 `starredIds.has(row.rec.id)` 这类拿记录 id 查收藏集合的写法）。

## 1.0.13 - 2026-10-08

- **修掉"放大不清晰"**（用户反馈：同样的图复制到别的软件放大是清晰的）
  - 根因：缩放原本用 `transform: scale()` —— 那只是把"适应窗口"时已经光栅化好的位图拉大，
    图片的真实像素根本没被用上，放大多少就损失多少
  - 改成按**真实布局尺寸**渲染（`width/height` = 基准 × 倍率），浏览器必须按目标尺寸重新解码采样；
    同时去掉 `will-change: transform`（它把图片锁成合成层、固定光栅倍率，放大必然糊）
  - 实测（`design/sharpness.cjs` 量化截图的高频能量）：放大到 **1:1** 时锐利度 1.368 → **1.875（+37%）**；
    这个倍率正是"看清截图小字"最常用的位置，也是别的软件无损的位置
  - 平移仍走 `transform: translate`（位移不影响清晰度）
- 顺带把"放到什么程度算到头"讲清楚：
  - 底栏改显示**实际读到的像素**（`naturalWidth`），不再只信宿主记的 `resolution`
  - 放大超过原始像素后，顶栏百分比变琥珀色，悬停提示"已超过原始像素 882 × 664（再放大也不会更清晰）"
  - 1:1 按钮的提示里带上它对应的倍率（如"166%"）
- 排除了两条误判：宿主 `clipboardManager` 是 `fs.writeFile(imagePath, buffer)` **原样存图**（无压缩、无缩略图），
  图片源没有问题；canvas 的 `imageSmoothingQuality: 'high'` 与 CSS 缩放渲染结果**完全一致**（量化无差异），
  所以没有改用 canvas 重采样
- `design/check-zoom.mts` 补到 101 项：新增"不得出现 scale / will-change"、"必须按真实尺寸渲染"、
  "超过原始像素要提示"等回归断言

  - 剪贴板内容不可信，`<script>alert(1)</script>` 这类输入只会作为文本显示，不会产出可执行标签
  - 引号不转义（着色结果输出在元素内容里，不是属性），否则 `&#39;` 里的 `39` 会被数字着色规则误命中

  - 刻意不采用"句子里出现过 npm"这种宽松口径 —— 那会把「我刚用 npm 装了个包，然后 git 提交」这种散文错判成代码
