# 新插件执行清单

## 1. 锁定范围

- 记录会话绑定的工作区绝对路径，后续所有读写都限制在该目录。
- 判断目录是空工作区、已有插件还是包含多个项目的仓库。
- 查找最近的 `AGENTS.md`，确认注释、测试和构建规则。
- 将用户明确要求和合理默认值整理成可验证的功能清单。

## 2. 选择结构

- 有交互页面时使用 Vue/Vite 模板；纯后台命令才使用纯 preload。
- 新建项目运行 `scripts/create_plugin.py`。工作区已经存在但为空时直接使用该目录。
- 默认使用精简模板。只有任务需要文件读写示例时才传 `--examples`。
- 检查一到两个相邻插件以了解主题和交互，但不要把旧清单字段作为规范。
- 生成器只负责创建项目结构；创建后必须立即完成 Logo 门禁，不能把模板 Logo 当作最终资源交付。

### Logo 门禁

- 根据插件定位设计独立 SVG 源图标，并保存源文件，不能使用模板或通用占位图标。
- 用 `magick`、`sips` 或其他可靠图像工具转换为 `plugin.json.logo` 引用的图片。
- 检查图片存在、尺寸、透明背景、清晰度和实际显示效果，并确认内容不等于内置模板 Logo。
- Logo 未替换或无法验证时暂停，不得继续 build、E2E 或交付。

## 3. 先定契约

- 先填写稳定的 `name`、用户可见的 `title`、本地 `main`、`logo`、可选 `preload` 和唯一 feature code。
- 删除模板中与需求无关的 feature、组件、依赖和 preload 方法。
- 对 `over`、文件、图片等输入设置类型、数量、长度、大小和扩展名边界。
- 将特权能力放在最小 preload 桥接中，页面只调用业务方法。

## 4. 覆盖状态边界

实现前逐项判断是否需要处理：

- 首次加载、空数据、损坏数据和版本升级。
- 重复进入、切换功能、退出后再进入。
- 跨日、跨时区、最大计数和重复提交。
- 取消、超时、过期异步响应和组件卸载清理。
- 正常尺寸、窄窗口、深色主题和减少动画。
- 宿主不可用时的开发预览降级，但不要复制第二套业务规则。

## 5. 形成构建闭环

```bash
npm install
npm run build
python3 <skill-dir>/scripts/validate_plugin.py <project-dir>/src-ztools
```

- 确认 `src-ztools/` 是可独立安装和压缩的插件目录。
- 确认 `src-ztools/dist/` 只包含 Vite 页面结果，清单仍以 `main: dist/...` 引用页面。
- 确认清单、Logo、preload 位于 `src-ztools/`，不重复复制到 `dist/`。
- `validate_plugin.py` 必须通过 Logo 文件、图片属性和模板 Logo 差异检查。
- 不创建自定义宽松校验器，也不把 `dist/` 单独当作完整插件目录校验。

## 6. 保留真实验证

```bash
npm run test:e2e
```

- 先让模板冒烟用例通过，再加入本次功能的业务断言。
- 用轮询等待真实状态，不用固定延时掩盖 Vue/React 更新时序。
- 持久化至少经过插件重新加载；关键数据经过隔离 Electron 重启。
- UI 声明以对应尺寸、主题截图或像素断言为证据。
- 将测试保留在项目内，便于后续回归。

## 7. 交付前复核

- 再次确认所有修改都位于绑定工作区。
- 区分已实现、已自动验证和尚未验证的能力。
- 报告插件目录、页面构建路径、触发词、构建和 E2E 结果。
- 只有用户明确要求时才额外生成 ZIP 或其他分发格式。
