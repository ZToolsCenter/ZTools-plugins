# Changelog

## 1.4.0 - 2026-10-29

### 新增

- 提醒支持分组：新建/编辑表单新增「分组」下拉，可选择已有分组，也可直接输入新组名创建；一个提醒最多归属一个分组
- 分组列表改为折叠块：顶层只显示分组入口（组名、数量）和未分组任务，点击分组原地向下展开组内任务，再次点击收起；切换状态 Tab 自动收起全部分组
- 组头提供组级操作：
  - **启动** / **停止**：批量启用或停用组内全部任务，只对状态需要变化的任务生效
  - **解散**：仅移除分组本身，组内任务保留并转为未分组
  - **删除**：连同组内全部任务一起删除，确认框会提示将被删除的任务数
- 列表支持多选批量操作：多选工具栏固定在状态 Tab 上方常驻显示，含**全选**（范围为当前可见任务）；选中任务后才出现**移入分组**（选择已有分组或输入新组名）、**移出分组**、**启用**、**停用**、**删除**、**取消**按钮，工具栏高度固定，勾选时列表不跳动；切换 Tab 时清空选择，收起分组时移除该组内已勾选的任务
- 分组与任务支持拖拽排序：拖动组头左侧手柄调整分组顺序；拖动任务左侧手柄可在组内调整顺序，拖到其他分组行可移入该组，拖到其他分组的任务上可按落点位置插入并换组，拖到未分组任务上即移出分组
- 新增排序字段 `order`，旧数据首次读取时按原显示顺序自动补齐，不影响现有排列
- 提醒支持一键复制：复制出配置、启用状态、所属分组都相同的新任务，标题追加「（副本）」，触发记录重置为全新任务
- 系统日志记录分组新建/解散/删除、组内批量启停、批量移入/移出分组、批量删除与复制操作

### 变更

- 编辑表单保存时会按分组下拉的取值解析真实分组 id；直接输入已存在的组名会复用该分组，不会产生重名分组

### 优化

- 列表项的启用开关移到复制/编辑/删除按钮同一行，垂直居中对齐，不再与标题行错位

## 1.3.2 - 2026-10-19

### 修复

- 修复同一计划时刻触发两次、重复弹提醒的问题：日志里同一任务出现 `16:30:00.020（偏差 +14ms）` 与 `16:29:50.813（偏差 -9193ms）` 两条 `[触发]` 记录。根因是系统时钟被回拨（NTP 校时、休眠唤醒后的时间补偿）时，定时器会按「修正后的挂钟时间」提前唤醒 —— 先触发一次，重排时 `Date.now()` 还差 9 秒才到计划时刻，于是把**同一个**计划时刻又算了一遍，9 秒后第二次触发。现在两处补上防护：
  - `triggerDue` 先校验是否真的到点：实际时刻比计划时刻早超过 1s 就不触发，记一条 `[自愈] 定时器提前唤醒，重新等待`，并按剩余时间重新排程（与既有的「错过补发」逻辑对称）
  - 每条提醒新增 `lastFiredSlot` 字段记录「最近一次已触发的计划时刻」，同一时刻再次进入触发流程只记一条 `[去重]` 日志、不再重复发通知，跨时钟跳变、多个插件视图各跑一份调度器时同样生效
  - 新建/编辑提醒时重置 `lastFiredSlot`，改了调度参数不会被旧的触发时刻挡住
- 修复编辑「一次性提醒」时初始日期会错一天：初始值原先用 `toISOString()`（UTC）换算，本地时间 00:00–07:59 的提醒会显示成前一天；改为按本地时区取年-月-日与时分

### 变更

- 系统日志时间戳由 `16:30:00.020` 改为 `2026-10-19 16:30:00.020`，跨天排查（如次日补发前一天错过的触发）不再分不清日期

### 优化

- 清理死代码（均为模板遗留或历史重构残留，不影响行为）：
  - preload 中从未被调用的 `readFile` / `writeTextFile` / `writeImageFile` / `notify` / `sendNotification` 五个接口，连同随之无用的 `fs` / `path` 依赖与前端类型声明一起删除
  - `useReminders` 中未被使用的 `reminders` / `enabledReminders` 导出
  - OnceForm / DailyForm / IntervalForm 三个表单子组件里没有监听方的 `defineEmits(update)`（结果本就由父组件调用 `getData()` 获取）
  - 提醒页未被使用的 `enterAction` 属性（App.vue 中对应的 ref 与模板绑定一并删除）
  - `OnceForm.getData()` 中父组件不消费的 `date` / `time` 字段，以及 `ReminderForm` 中只写不读的 `form.triggerAt`

## 1.3.1 - 2026-10-16

### 修复

- 修复「电脑重启、ZTools 自启后提醒任务不启动」：ZTools 只在创建插件视图时才执行 preload.js（用户打开插件，或在插件设置里勾选「跟随主程序同时启动运行」后由主程序启动时后台预加载）。此前调度器只在 preload 模块加载那一刻排一次程，只要当时宿主 API 尚未注入 / 存储读取失败 / 提醒列表还是空的，`calcNextTick` 返回 null 就再也不会重排，直到用户手动打开插件并做一次增删改才恢复。现改为显式 `init()`：宿主未就绪时按 300ms 快速重试（约 12s），之后由 30s 一轮的看门狗长期兜底，插件视图一创建就把内部任务调度起来
- 修复调度链被一次异常打断后永久停摆：触发时的存储写入、系统通知抛错会导致 `scheduleNext()` 不再执行；现在触发失败会记一条 `[异常]` 日志并按 30s 退避重试，重排一定会执行
- 修复睡眠/休眠唤醒、系统时间跳变后错过的触发无人补偿：看门狗发现「排程时间已过却没触发」时，5 分钟内补发提醒（日志记 `[自愈]`），超过 5 分钟视为陈旧触发，跳到下一次不再补发
- 一次性提醒在触发状态写库失败时不再重复通知（会话内已发过的 once 提醒会被记住），且每轮触发都会重试把「已触发」状态写回存储，避免写库故障期间过期数据一直占住调度、拖累其他提醒

### 新增

- 系统日志新增 `[启动]` 记录：调度器就绪时刻、提醒条数（启用数）、下次触发时间，并带 `hostReadyAtLoad` 诊断字段（preload 执行那一刻宿主 API 是否已注入），排查「不提醒」时可直接从日志定位
- 首页底部新增调度状态：`调度中 · 下次 今天 11:00` / `调度中 · 暂无待触发` / `调度器未就绪`，鼠标悬浮显示「跟随主程序同时启动运行」的设置路径
- `plugin.json` 声明 `pluginSetting.backgroundRunning: true`：ZTools 对后台/隐藏的插件视图默认开启 `backgroundThrottling`，声明后自启的隐藏视图不被节流，长时间挂后台触发更稳

### 优化

- 节假日数据改为后台每小时自检一次：插件视图长期驻留（不再随 ZTools 重启重建）时，跨年、次年安排公布也能自动补数据；此前只在 preload 加载时检查一次
- 节假日缓存改为「宿主就绪后首次使用时读取」，避免 preload 早于宿主 API 执行时把空缓存固化下来
- 进入插件时立即重排一次调度，不必等看门狗巡检；移除未被使用的 `stopScheduler` 接口

- 节假日数据状态行从列表底部移到顶部标题行（「新建」按钮左侧），列表区域更清爽

### 优化

- 新建提醒时星期默认全选
- 系统日志精简重构：去掉每次调度重算产生的「[调度] 定时器」刷屏，只在任务新建/修改/启用/停用/删除时记录一条状态（含下次触发时间），任务触发时记录一条执行记录（计划时间与偏差）；修复渲染层与调度器重复记录同一事件导致日志翻倍的问题
- 日志「复制」按钮不再附带冗余的 detail JSON，只复制时间与消息正文

## 1.2.0 - 2026-09-21

### 新增

- 间隔提醒支持「触发对齐」选择，由用户决定触发相位：
  - **按开始时间对齐**（新建时默认）：触发点 = 开始时间 + N × 间隔，与创建时刻无关。例：09:00–18:00 每小时 → 9:00、10:00、11:00…准点触发；错过一次（如电脑睡眠）不影响后续准点
  - **按创建时间起算**：从创建时刻起每隔一个间隔触发。例：10:30 创建 → 11:30、12:30…
- 列表中「随创建时间」的间隔提醒显示标签，便于区分对齐方式
- 间隔提醒「统一时间」开关真实生效：开启时所有选中星期共用同一组时间段，关闭后可分别为每个星期设置不同的时间段；此前该开关不改变实际行为
- 「提醒时间段」标签与「统一时间」开关增加鼠标悬浮说明
- 新建/编辑提醒时，三种提醒类型选择框下方新增一行说明文字

### 优化

- 「调试日志」更名为「系统日志」
- 定时提醒的默认提醒日期由第二天改为今天

### 说明

- 历史数据自动视为「按创建时间起算」，行为不变；编辑时可在表单中切换
- 评估过引入 cron 表达式，暂不做：cron 无法表达法定节假日/调休过滤（插件核心能力），且现有三种类型 + 触发日过滤已覆盖主要场景

## 1.1.0 - 2026-09-21

### 新增

- 提醒支持按「法定工作日 / 法定节假日」过滤触发：新建/编辑每日提醒、间隔提醒时可选择触发日（不限 / 仅工作日 / 仅节假日），在原日期选择基础上进一步过滤，节假日判断含调休补班日
- 节假日数据自动维护：进入插件时检查本地缓存，缺哪年就自动拉取一次（timor.tech API，含当年全年数据；12 月起顺带补次年），已有数据则不做任何请求，无需手动维护
- 首页新增节假日数据状态栏，展示数据覆盖年份与更新日期，支持手动「更新数据」
- 断网降级：API 不可用时使用本地缓存判断；缓存也为空时按自然周（周一至五为工作日）近似，并在状态栏提示

### 优化

- 「下次触发时间」计算支持跨节假日顺延：例如「每个工作日 09:00」的提醒会自动跳过法定假期，顺延到调休上班日或假期后首个工作日

## 1.0.0 - 2026-08-27

### 新增
- 三种提醒模式：间隔提醒、每日定点提醒、一次性定时提醒
- 调度器运行在 preload 层，插件后台运行也能稳定触发通知
- 支持自定义提醒标题和内容
- 间隔提醒支持多时间段、自定义间隔（分钟）
- 每日提醒支持选择星期几和具体时间
- 一次性提醒支持选择日期和时间，触发后自动禁用
- 提醒列表支持启用/禁用开关
- 调试日志面板（默认关闭），方便排查问题

### 优化
- 动态调度算法：精确计算下次触发时间，偏差 < 20ms
- 系统通知：标题显示任务名，内容显示描述
- 数据持久化：使用 ZTools dbStorage，数据随账号同步

### 技术
- 基于 Vue 3 + TypeScript + Element Plus
- 调度逻辑在 preload 中运行，不受渲染进程节流影响
- 响应式数据流，操作即时反馈
