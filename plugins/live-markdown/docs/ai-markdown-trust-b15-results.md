# Markdown Harness 调整与真实模型复测

日期：2026-10-25 至 2026-10-26，America/Los_Angeles。

## 验收结论

本轮完成了 Harness 改造和真实模型复测，**正文编辑质量验收仍未通过**。B15 应作为测试版；不能以自动化检查通过、出现 Diff 或确认/撤销成功，替代模型完成任务的证据。

已证实协议和输入组织会影响结果。1.7B 在独立自然 Markdown 对照中只修正了两处错字，原有代码与数字完整保留；生产分片与提示组合下仍漏改同样的错字。当前问题同时涉及模型能力、提示与分片上下文敏感性，不能单独归因于 JSON schema 或 token 上限。

## 实现范围

- 本地润色、校对改为直接生成自然 Markdown，取消正文 JSON 槽回执与输出 schema；原执行路径继续用于其他供应商和旧协议调用。
- 以完整句子及完整行内语法组织输入，按上下文和输出预算合并连续原文片段。代码块、表格、标题、frontmatter、脚注定义、块公式、独立 TOC 由程序保留。
- 正文与摘要复用语法分句器，避免在链接查询参数、代码、强调、公式、转义标点和脚注引用中切断语法。保留原始 UTF-16 范围与 CRLF/LF/CR 字节序列。
- 允许等价列表分隔符、同级标题写法。自然正文路径中的粗体/斜体调整进入 Diff 提示；代码、URL、公式、编号、任务状态、删除线、段落与引用结构继续校验。
- 数字、单位、上下标、图标、明确状态、否定限制及名称仍受保护；“通过快捷键”按语境识别，避免机械当成“验收通过”。这些是保守锚点检查，不能证明任意语义等价。
- 默认摘要约 400 字、最多 5 条可选事实；关键事实全部保留，无法压缩时提示。支持“12 条”“3 个要点”“最多 5 个字”等约束；无法用完整事实满足时明确拒绝。
- 摘要预算测量使用纯排版计算，避免逐候选重复解析全文 AST。保留 1 MiB 输入/候选、50 组、共享调用/时间/输出预算、取消和版本检查。
- 全部分片先暂存，通过后只生成一次完整提案；不新增自动修复重试。保留完整 Diff、确认写回和一次撤销。

主要实现位于 `src/core/ai/naturalProsePlan.ts`、`naturalProseExecution.ts`、`proseEditPlan.ts`、`markdownSentenceBoundaries.ts`、`markdownAstIntegrity.ts`、`proseEditFactGuard.ts` 和摘要模块。本轮修改的源码文件均不超过 500 行。

## 自然输出控制实验

独立服务层实验使用同一模型、温度 0、上下文与后端，每模型执行一个完整句子和一个九句片段，共 4 个新请求。九句内容逐字来自先前生产请求；同时移除了 JSON schema、回执提示并改变了输入打包，因此不能只归因于 schema。

| 控制任务 | 0.6B | 1.7B |
| --- | --- | --- |
| 单句校对 | 修正“提拱”，额外加入“与” | 修正错字，但删除粗体标记 |
| 九句 742 字符片段 | 未修两错，遗漏末尾两句 | 仅修两错，逐字等于期望稿；14 个行内代码片段及数字均保留 |

该片段没有真实 Markdown 链接目标，不能据此验证链接保持。0.6B 的遗漏发生在正常 `stop`、输出远低于请求上限时，不能当作 token 截断。一次自然输出成功也不能推导所有长文或分片稳定成功。
