## 已修复的执行层问题

1. **多标题和固定 JSON。** 有序标题集合保留每项原文证据、级别、数量和顺序；引号内逗号及重复标题不会丢失。完整、明确的 JSON 对象和数组由程序构造，包括嵌套数据、false、null、Unicode 和元素顺序。动态值、来源派生值、额外操作不会被当作完整字面量。数量矛盾在模型调用前停止；仅未给定标题内容仍允许生成。
2. **JSON 与草案提示。** 去掉会诱导复制的 `ok:true` 示例和章节省略号示例。章节正文由模型写，程序固定标题；整句复述任务、纯占位内容和未声明标题不会当作完成正文。开放草案仍须人工检查主题、具体程度和事实。
3. **表格字段角色。** 列清单不再把尾随的“保留单位”“不能交换关系”等要求误读成第三列；声明列数和列名冲突不会猜测。来源价格识别英文 `yuan`、`costs` 和 `per month` 等关系，校验主体、完整金额及币种/计价单位；兼容 `Price / Unit` 复合列。
4. **润色的切槽。** 修复大小写不敏感的三字母货币码规则吞掉 `have` 的 `ave`，不再装配出 `hasave`。日期、金额句的冒号标签和纯标点保持源码所有，不要求模型回传；首尾/边缘标记按明确保护要求留在源码。
5. **小模型的可读正文路径。** 仅对本轮实际评测的两个缓存 Qwen ID，且全部正文槽位位于同一物理行时，先构造可读行再调用模型，避免要求模型逐个操作碎片 ID。强调和链接标记从视图移除，URL 与链接标题隐藏，代码/公式等用不可改占位词。程序通过文本差异把修改投影回唯一正文槽，再经过原有结构、事实和整文装配检查。

可读路径的边界为：原始物理行最多 8,192 codepoints、视图最多 512 codepoints、最多 128 个槽，模型输出最多 1,024 codepoints。投影不能跨只读文字、数字、单位、占位词或多个槽；空白/清空槽、控制符和超限输出拒绝。首尾标点和 emoji 也在授权范围内核验。无法适用时，在调用前选择原有分批槽位路径；推理失败后不重试、不换协议补调。

普通分批路径增加有界的可读上下文和语法目标；完整预算预检、全部分片完成才形成一次 Diff、确认后写入、一次撤销、版本保护和取消保持。没有引入模型裁判、自动切换模型、执行生成代码或下载新权重。
