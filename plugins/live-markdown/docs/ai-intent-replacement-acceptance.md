# Live Markdown 局部替换问题验收

日期：2026-10-23。范围：`底部hello改成helloworld`、唯一／全部／最后一处替换，以及追加回归。本机使用已缓存 Qwen3-0.6B-Q4_K_M；没有下载、换模型或写入用户文档。

## 原因与修复

旧版只验证了追加。五句替换指令的真实模型基线共15次，15次均在协议阶段失败：模型混用新增与替换字段、把底部输出为 `document_end`，或缺少 `find/occurrence`。冷请求和热请求都能复现，不能归因为“首次必须失败”。没有用户截图那一次的原始响应，因此这里只认定同句本机复现结果。

- 替换目标是全文／选区；底部替换绑定范围内最后一处精确匹配。
- 指令中的原始数据分别作为候选，模型选旧文 `findId` 和新文 `literalId`，由程序取回原文。没有规则直接执行自然语言操作。
- 每次字面替换仍为一次意图规划、零次内容生成，无自动重试，也不回退到全文改写。
- 只增加提示示例的两轮预检仍然失败，均保留原始结果。最终规划接入 managed 引擎的闭合 schema 解码，限制完整字段和已 grounding 的位置选项；操作和旧／新文角色仍由模型选择。一次真实 sentinel probe 已验证引擎执行约束，并非只做请求后的 JSON 检查。
- 引用、替换数据或否定的末尾文字不能授权最后一处；选区、只读、快照过期和 AST 保护继续生效。
- 新文字的 Markdown 前缀完整保留。最后一处扫描只保留一个位置，避免长文驻留全部匹配对象。
- Diff 确认后才写入；一次撤销恢复完整原文。

## 实验记录

| 阶段 | 检查层 | 结果 |
| --- | --- | --- |
| baseline | 五句真实替换、严格协议 | 0/15，全部拒绝 |
| prompt-preview | 三句单次推理，仅检查响应字段 | 1/3符合目标 |
| prompt-preview-v2 | 压缩提示后的三句单次推理、格式与字段 | 0/3符合完整协议 |
| schema-probe | 提示要求非法值，schema仅允许固定sentinel | 1/1，真实引擎执行约束 |
| prompt-preview-v3 | 接入约束后的三句单次推理、格式与字段 | 3/3符合目标；不是完整验收 |
| fixed | 11句各3次，完整补丁与runner／AST oracle | 28/33；未交付为修复完成 |
| fixed-v2 | 相同11句各3次、相同完整oracle | 27/33；替换24/24，追加3/9，未交付为修复完成 |
| fixed-v3 | 按数据形状选择示例，相同完整oracle | 30/33；仍有3次回答／编辑误判，未交付为修复完成 |
| fixed-v4 | 仅结构化规划使用temperature=0，相同完整oracle | **33/33**；冷请求11/11、热请求22/22 |

`fixed` 的失败保留：4次追加被误判为回答，1次“草案→终稿”仍选原词作新文。随后补充普通追加示例；按旧词ID排除相同的新文ID；完整runner另外阻止零变化提案。无自然语言规则直接执行操作，模型仍选择操作和数据角色。

`fixed-v2` 的6次失败全部为追加误判成回答。下一版按候选的数据形状检索示例：仅一个literal时不加入成对旧／新文字示例，仍保留所有操作规则及回答示例；两个以上literal继续示范新旧文角色。示例检索不决定实际操作，也不缩小允许的操作集合。

`fixed-v3` 仍有随机误判。缓存引擎的 `--help` 确认默认 temperature=0.80，旧 transport 没有覆盖；最终改为仅带 outputSchema 的 managed 规划请求设置 temperature=0，其他内容生成请求保持原采样配置。

`fixed-v4` 每条只有一次真实模型调用，无自动重试、无下载；11句分别为三种基本替换语序、带引号替换、全部替换、最后一处foo、中文草案／终稿、版本号替换，以及原有三种追加。全部原始JSON通过协议和绑定，补丁与完整文稿oracle一致；相同33份真实JSON回放到完整runner后，AST和最终原文比对亦33/33，回放没有新增模型调用。最后一处foo和中文替换含重复原词；浏览器另验证重复hello只改文末。

冷请求指每句重新建立服务后的首条，不清除OS缓存，不代表整机重启。当前macOS arm64的generate调用耗时中位数322ms、P95 1132ms、最大1435ms，仅为该缓存模型、该次样本的观察结果。测试结束后managed服务已释放。

本次不将单元测试等同真实模型或原生宿主验收。各版本是源码发生变化后的独立复测，不是产品对失败请求的自动重试，也没有筛掉失败响应。

## 限制

自由自然语言的操作和数据角色仍由模型判断，严格协议与 AST 不能证明模型理解了所有意图。重复匹配而未指定位置时请求消歧；原文不存在时保留可编辑指令；受保护代码／链接等内部的修改照常阻断。本次不表示完整50例门槛、原生 ZTools 或 Windows／Linux 实机已通过。

额外三条边界真实planner检查只有1/3符合分类oracle：引用解释正确为answer；纯否定也输出answer而非clarify；复合编辑漏识别第二步。没有把它们混入33条编辑成功率。对这三份真实响应作最终runner策略回放：解释和否定只在助手回答，不产生提案；复合编辑被既有多操作守卫拦截，三条均不写文档。回答正文在回放中为受控stub，不是额外模型测试。因此本轮修复了已列出的字面编辑用例，不宣称0.6B已理解所有自然语言或满足完整意图准确率门槛。证据：`fixed-v4-guard/guard-report.json`、`current-runner-policy-replay.json`。
