# 默认薄执行层 B30 验收记录

本轮目标是降低普通编辑的调用成本，并移除不必要的格式拒绝；保留范围、版本、取消、只读、Diff 确认和撤销保护。实现与包体在开发 worktree 中验收，不替换用户已安装插件，不修改用户文稿，不提交或推送。

## 用例与比较口径

准备了 79 条用例、18 个任务族，涵盖追加、精确替换、选区/光标、标题、Markdown/Python/JSON 代码、表格、公式、Mermaid、图标、润色、开放写作、问答、长文及否定/复合/权限/取消。25 个代表用例使用两个真实缓存模型各运行 direct/thin/full 三路，共 150 组路由对照。其余 54 条为受控边界矩阵；矩阵条目数不等于已执行或已通过的产品任务数。

direct 使用同样的范围绑定与简短正文提示，但不启用内容编译；thin 启用程序确定性执行；full 为当前源码中的显式完整流程。三路是管线比较，包含提示词、协议及采样方式差异，不能把调用量差值解释成严格单变量实验。schema 调用的 temperature 为 0，正文调用沿用后端默认值，无固定 seed。耗时包含冷启动影响，token 为本地估算。

每条结果分别记录任务效果、范围、Markdown 格式、显式参数、开放语义和写入安全。可审查提案不是语义正确证明；需要人工判断的结果不会记为自动通过。终止、澄清、失败、截断和未变化分别保留。

## 首轮暴露的问题

原始首轮证据保存在 `.cache/acceptance/thin-harness-b30-20261027/b30-final-{light,balanced}/`。目录中的 `final` 是当时运行标签，不表示最终交付版本；冻结源码与原始失败没有被重写。

| 输入类型 | 确认的程序问题 | 修正方向 |
| --- | --- | --- |
| 冒号后的原样追加 | 冒号误入 payload | 分隔符与用户正文分离，保留精确源码跨度 |
| 引号内追加 emoji | 布局未知导致 literal 丢失并被拒 | 基于已绑定位置统一默认布局，保留 literal 模式 |
| 选区整体替换 | 新值被当作 find，要求选区出现新值 | 选区自身是被替换范围，不要求虚构旧词 |
| 唯一 Markdown 标题 | 仅识别带引号标题引用 | 使用 Markdown 标题引用和真实 AST 唯一绑定 |
| 润色且只纠正一个词 | broad rewrite 与 narrow replacement 被判冲突 | 唯一 grounded find/write 收敛成选区内一次精确替换 |
| 转换为表格且不加第三项 | 狭窄内容禁止被当成全局不编辑 | 正向转换与内容限制分别保留 |

同时修正了评分器的四类误判：价格数字与单位之间的非语义空格；TABLE03 原句未要求追加，应期待全文转换；HEAD01/04 的空行归属可不同但完整提案字节相同，现采用章节结束的标准锚点；POL01 既可替换整句，也可仅替换错词，评分依据选区授权范围与完整最终文档是否逐字正确。代码评估额外检查未闭合的外围及 Markdown 嵌套围栏。早期证据继续采用当时冻结的评分器，最终 R3 重新运行全部代表用例，不混用不同版本的自动评分。

## 最终验证

最终模型证据为 `.cache/acceptance/thin-harness-b30-20261027/b30-r3-{light,balanced}/`，两份均完成 25 条 × 3 路。源码/矩阵/脚本在运行前后核验冻结身份。中间 R2 和首轮均原样保留；R2 暴露的英语 all 限定词与函数标识符 `add(a, b)` 误当命令的问题已在 R3 前修正，另有生产入口回归。

“自动完成约束”仅指该用例的确定性格式/参数/范围检查完成，不是所有内容均正确。预期安全澄清是重复标题用例，不算创作完成；未变化且未完成请求的润色结果计失败。

两模型合计，thin 使用 32 次模型调用，direct 52 次、full 61 次；输入 token 估算分别为 17,989、22,835、144,945。此差异来自整个执行策略及确定性编译，不应外推为所有工作负载的性能提升。每个模型各有 10 个确定性编辑零调用完成，重复标题零调用澄清；长文问答使用 3 次来源分批请求。最终 150 组对照没有自动写入测试文稿，也没有来源对象被突变。

程序回归全部通过：124 个 unit 文件、1,409 项；preload 87 项；集成 5 项；Chromium 浏览器 133 项；评分器 17 项。类型检查、构建完整性、15 MB 上限和 ZIP CRC 检查通过。浏览器计数采用 Node 测试计数（包括父测试），不代表 133 条互不重叠的模型任务。

最终浏览器回归曾出现一次 Skills 保存后立即 reload 的测试时序失败（132/133）。同构建单独复跑通过；测试改为等待存储内同一技能 ID 的新名称及模板已保存，并在删除落盘后重载，不使用固定 sleep。最终完整重跑 133/133、无 skip。最初日志 `e2e-r3-initial.log` 和单独复核日志保留，未将失败隐藏为通过。

独立语义复核覆盖 7 类复杂任务 × 2 模型 × 3 路，共 42 条，结果为 **14 通过、20 失败、8 未产出所需结果**。这不是整个 150 组的统一成功率。选区事实问答六路均正确；1.7B 的 direct/thin 能覆盖长文开篇、中段和末段事实。代码任务仍有标题或围栏问题，开放写作未形成要求的小标题结构，润色未能同时完成正文改善与结构保留，部分通用问答仍有错误。小模型复杂生成没有获得全面验收，薄执行层主要消除了程序误拒和重复调用。

## 验证边界

本轮模型运行使用验收目录中的缓存权重，不下载模型；测试输入均为合成数据。核心和 Chromium 浏览器结果不能代替 ZTools 原生宿主、Gemini、Windows 或 Linux 本机验收。模型仍可能返回格式错误、缺项、错误事实或未作有效润色。可检测的格式问题会显示提示，候选修改需要 Diff 确认；程序不保证识别全部事实或缺项，也不会把可审查当成自动正确或自动写入。
