# B33 数字保真、代码正文与写作质量复测

日期：2026-10-28（America/Los_Angeles）。开发工作区为 `codex/live-markdown-harness-b13` 对应 worktree；用户文稿、已安装插件与模型配置均不修改，不提交或推送。B32 源码、ZIP 和模型证据保留。

## 改动范围

- 润色中，唯一匹配且其余文字完全相同的只读整数片段，可将模型返回的英文数词还原为原文数字，再走原有严格源码投影和事实检查。仅覆盖 0–99；日期、小数、正负号、百分比、标识符、重复或复合数词等不猜测。单位、顺序、金额及占位词保护没有放开。
- JS/TS/JSX/TSX 生成正文通过有界 Lezer 语法解析，不执行代码。只在明确要求的标题隔开两个相同代码副本，且第二份是同语言围栏、没有多余内容时，移除重复外壳。不同代码或模糊包装仍停止。其他语言明确提示尚未做语法解析；解析无错误不等于类型、行为或依赖正确。
- 英文 `with these headings in order:` 清单进入现有结构化章节生成流程，保留原标签证据和顺序。未加引号的“标题 + 列表/段落/表格”不会整句吞成标题；尚未表达完整的内容交由模型填写。带引号的标题仍按字面保留。

没有新增重试、模型裁判或自动切换模型。复合内容原来被错误标成零调用的情况，修复后会发生一次必要的内容生成调用；不能再把漏内容的零调用称为成功。

## 未采用的提示词试验

R1/R2 尝试了通用语法提示、专用 copyeditor 提示与章节角色指导。8 次短探针对两个模型的链接句都有改善，但完整 R2 的旧 64 条基线仅 **52 通过、8 失败、4 未产出**，低于 B32 的 60/64；新增变体的局部改善不能抵消基线回归。因此最终 R3 的 `readableProseTask.ts` 和 `artifactSectionFill.ts` 已逐字恢复为 B32，并保留全部模型报告、原始回执、试验提示词副本和复核记录。

最终旧基线 32 类、两个模型的实际 `prompt/systemPrompt/outputSchema` 与 B32 R4 逐条一致。剩余同请求不同输出反映采样不稳定或模型能力边界，不能归功于本轮提示词优化。R1 的目录名 `b33-final-*` 是历史探索标签，不能当最终验收；最终只采用 `b33-r3-*`，不选取不同轮次的最好结果拼接。

## 复测口径

原 B32 的 32 个场景原样保留，另加 12 个代码、数字、链接、正确句子与中英文草案变体。两个缓存模型分别运行 44 个默认 thin 流程；固定结构可零调用，其余按原预定流程生成。格式通过、被门禁拦截与内容质量通过分别记录。真实模型与独立人工复核结果以最终证据为准，不能把测试通过数当作模型任务数。

最终报告：`.cache/acceptance/content-quality-b33-20261028/b33-r3-{light,balanced}/report.json`。独立复核 `manual-r3.json` 逐条绑定输入、原始回复与 observation 哈希；完整交付身份 `delivery.json`。两模型冻结的 src/preload 树 SHA-256 为 `747d60e985298adb3bd6986cc6f31b4f88eed3e85fec8fcaadd5057aa354d72a`。

两个模型各 29 次调用，总计 58 次；88 个流程均未自动写入，来源对象指纹保持不变，仅使用已缓存资源，下载字节为 0。没有固定 seed，也没有据并行运行耗时声称性能提升。

旧四项缺口中：重复 TypeScript 代码和整数数词保真在本轮通过；0.6B 链接句本次改对，但前两轮仍失败，不能称为稳定修复；发布演练草案两模型仍有空泛或偏成应急演练的问题。0.6B 的带行内保护原子和 CRLF 文档校对本轮原样返回错误句；相同请求的输出变化不能被掩盖。

新增变体仍失败的类型包括：多数字句或百分比句漏改、已正确句子仍被改写、代码旁的动词一致性漏改、草案偏题或仅列类别。四个未产出是：0.6B 异步 TypeScript 输出残缺围栏；1.7B 代码模板返回有效代码加空围栏；两个模型的 Markdown 代码块把明确的一号标题写成其他文字或二号标题。保守门禁停止且原文未修改，这些均不算完成请求。

人工标准仍以实际指令为准：`B31-CODE-H4` 只要求“定义 run_check”，没有限定函数；变量定义可以满足该原话。旧自动 `functionName` oracle 过窄，不能在 B33 复核时反向增加用户要求。复核文件中保留这项口径说明，其他判定不据通过率调整。

## 已知失败回放与程序回归

`known-failure-replay.json` 将相同 B32 原始回复交给冻结 B32 和最终 B33：旧版把 `three` 误拦，新版还原原 `3` 并保留语法改动；旧版接受 TypeScript 重复 Markdown 外壳与残缺函数，新版清理唯一重复副本并拒绝残缺语法。这是确定性的修复证据，不等于所有新生成代码都正确。

复核时发现复合数词 `one hundred [and] three` 曾可能被误还原为 `3`，已先用实际投影回归复现再修复。扩展平面字母/组合符号边界另有辅助函数回归；指定的完整投影场景修复前已拒绝，不能声称捕获了用户数据损坏。

最终单元测试 **1,619 项 / 147 文件**、preload **87 项**、集成 **5 项**、Chromium **146 项**、评分器和矩阵 **26 项**通过；类型检查、JSX 检查、构建与 dist 完整性通过。浏览器数量含父测试，不能当作 146 次真实模型调用。新增浏览器用例覆盖等价数词恢复、相同代码副本、无效代码停止且指令可修改、英文草案标题，以及代码块中的标题与列表；均检查确认前不写入、一次确认和一次撤销。
