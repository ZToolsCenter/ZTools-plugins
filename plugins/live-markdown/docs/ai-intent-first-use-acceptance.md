# Live Markdown 无选区首次请求问题验收

日期：2026-10-23。范围：截图中的“底部加个hello，world”及带空格的变体，当前本机 Qwen3 0.6B、macOS arm64。

## 结论

不是“第一次必须失败”的服务状态逻辑。旧版可在冷请求和热请求复现同样的范围冲突。没有本次用户原始模型 JSON，不能断定截图究竟是直接返回 scope_conflict，还是错误选区目标被 planner 转成该文案；两条可达路径都已处理。

旧提示同时提供有／无选区示例，且普通追加也发送全份标题候选。模型会套错选区状态，或复制 payload 时改动标点和空格。旧代码又把模型范围错误描述成用户选区不明确。

## 改动

- system prompt 按程序的真实选区状态构建；无选区不再提供选区操作示例。
- 新增 intentContext，仅提供相关标题／章节候选；普通文末追加不附带整份目录。
- 无选区时模型生成选区目标或 scope_conflict，提示模型计划不符；用户明确请求不存在的选区时要求先选择，不扩大为全文。
- 有选区时，全文润色仍为 rewrite/document，只有文末插入才为 document_end。
- 引号候选优先；无引号时允许采集有 Han 前缀、后续无 Han、最多256字节的 ASCII 尾部作为数据候选。模型仍需识别操作和目标，选择 literalId 后由程序取回原文，不改写标点和空格，不以规则直接执行。
- 保留严格协议和 AST、快照检查，仍然每请求一次规划，无自动重试。
