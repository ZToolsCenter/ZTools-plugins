# B34 任务粒度与代码意图修复复测

日期：2026-10-28（America/Los_Angeles）。工作区为 `codex/live-markdown-harness-b13` 对应 worktree；用户文稿、已安装插件和模型选择未改，不提交或推送。B33 的报告及命名 ZIP 保留。

## 修复范围

1. **源码约束的正文任务。** 对两款已评测本地 Qwen，推理前按物理行及安全句末划分完整任务，仍从整行 Markdown AST 取得范围。受保护代码、公式、链接和数字不能被切开或改写。所有槽覆盖原始范围且只覆盖一次，片段之间的空白由程序按原源码恢复。中文全角句末无需空格也能切分。整行不可用时，将相邻完整短句按 256 codepoints 上限合并，避免逐句调用爆炸；960 个汉字、40 个连续句的单测从 40 个任务减少到 4 个。可读视图仍限 512 codepoints，最多 50 个任务；无法安全划分则在推理前保留现有路径。这是确定性计划/装配验证，不是该长文的真实模型质量验收。
2. **完整装配与预检。** 所有预定正文请求在首次推理前检查调用和本地 token 预算。任一片失败、取消或版本变化，不形成部分写入；完成后只产生一次 Diff，确认后写回且一次撤销。原章节生成仍使用一次完整的结构化请求。
3. **代码需求证据。** 明确提到的函数名与异步要求传入生成请求；JS/TS 用 AST 检查请求对应的函数绑定。描述、否定或保护已有函数不会反向变成新增函数要求。“定义 run_check”未限定函数类型，仍保留原含义。
4. **已知结构与可恢复外壳。** 完整明确的 Markdown 标题加单项列表/字面段落由程序组装，未明确内容不猜测。合法代码后唯一的精确请求标题与空语言围栏可作为重复外壳移除；不同正文、额外结构和未闭合代码仍不择一。支持有界恢复重复语言关闭围栏，恢复后仍检查代码语法和用户明确的异步要求，不将同步函数改成异步。

## 撤回的实验

R1–R3 试验了逐章节调用，尝试目录证据屏蔽、移除编辑器控制语句、只保留当前节主题以及结构溢出校验。真实结果仍有复述指令、章节互相混入、偏题和额外调用成本，未证明稳定收益。最终恢复原有一次结构化章节请求，实验源码/单测移入验收目录的 `rejected-section-plan/`，不进入发行包和运行路径。最终仅采用 R5，不从不同轮次抽取最好结果拼接。

R4 又发现部分非异步代码请求因重复添加名称/函数体提示而退步。最终对三个既有代码场景恢复与 B33 完全一致的生成提示，函数名的新增证据仍用于结果校验；异步 TypeScript 的必要提示单独保留。`code-prompt-compatibility.json` 记录三项逐字比较，不将采样波动当作确定性收益。

原 15 项未通过中，本轮 7 项通过、8 项仍失败；原 4 项未产出均出现了可审查候选。另有 3 项原通过出现质量回退：0.6B 链接句漏改主谓一致、0.6B 代码旁动词 `use` 漏改、1.7B 异步 TypeScript 返回类型仍错。逐项 before/after、理由、请求和原始结果指纹保留在 `manual-r5.json` 的 `targeted15` 与 `regressions`。没有从不同轮次挑选最好结果。

仍未解决的原因分为：

- **模型漏改或只改一处。** 0.6B 的 CRLF 文稿仍保留错误句；1.7B 多数字与百分比句仍有 no-op；含代码句可能只改 `have` 而漏掉 `use`。核对 raw 即可看到错误已经存在，不能归因于写回丢失。
- **开放写作内容不足。** 发布演练仍可能只给阶段/类别或偏成应急演练；0.6B 的英文演练仅拟定另一份计划，没有实际演练动作。目录正确不能证明内容完成。部分短句同请求在不同轮次有不同结果，不把一次通过称为稳定修复。
- **模型类型错误。** 1.7B `async loadLabel(...): string` 语法可解析，但 TypeScript 报 TS1064。明确的 Promise 提示仍未完全消除问题。生产只做有界语法/函数属性检查并提示未执行类型检查；不声称生成代码可运行。

对“定义 run_check”继续按实际原话允许变量定义，不因旧自动 oracle 的 functionName 字段增加用户未提出的函数要求。多数字句的主体指代与语言习惯也需结合上下文解释；没有加入按测试词语硬改语法的规则。
