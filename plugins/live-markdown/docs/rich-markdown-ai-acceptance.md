日期：2026-10-21（America/Los_Angeles）。本机：Apple M5、32 GiB、macOS ARM64。插件版本：0.1.0。

本记录保留 Harness 更新前的固定样本。更新后的固定输入比较、完整性门禁和剩余限制见 [Harness 验收](./harness-ai-acceptance.md)，新一轮观察不覆盖或抹去下面的历史失败。

## 已修复的工程问题

- 表格改用共享 GFM 单元格解析，正确处理 `\|`（含代码跨度内）、列对齐与行宽；实时单元格支持粗体、链接和行内公式。链接交给宿主回调，脚本文本不执行，组件销毁时释放 React root。转义管道规则参照 [GFM 表格示例](https://github.github.com/gfm/#example-200)。
- AI 插入 Mermaid 等块内容时，补足与前后原文之间缺少的空行；不裁剪原文、不改写生成内容，保留 CRLF。确认后的真实源码与预期逐字比较。
- 源码、阅读、实时模式之间切换后保留同一文稿的撤销记录；通过文稿身份与内容校验隔离历史，重新建立当前回调与只读配置。一次撤销可恢复整次 AI 插入。
- 修复正文硬换行之后的独立单行／多行 `$$` 公式预览，只隐藏公式自身范围。代码字面量和链接地址中的美元符号不作为公式；公式前后的粗体仍保留。按语法范围及顺序游标处理，避免逐个匹配反复扫描全文；不自动纠正与正文粘连的分隔符，也不修改公式含义。整行 `$$表达式$$` 的形式可参照 [GitHub 公式文档](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/writing-mathematical-expressions)。

专用浏览器回归还检查了复杂表格点击进入源码、重新生成预览、链接不跳离插件、转义代码、脚本文本安全、图表显示、公式与粗体/代码混排，以及视图切换后的整次撤销。截图：[复杂表格](../.cache/e2e/screenshots/rich-table-preview.png)、[图表插入](../.cache/e2e/screenshots/ai-diagram-insertion-boundary.png)、[公式混排](../.cache/e2e/screenshots/rich-formula-preview.png)。公式混排回归曾在修正前真实失败，修正后再验收。

## 仍需明确的边界

- 润色和自定义替换会保护已有表格、代码围栏、公式、链接及 frontmatter。因此“修改已有表格某个单元格／已有公式”目前不属于这一编辑路径的能力；新增结构与插入任务可以产生表格或公式。原文不变不能算编辑成功。
- 保护校验可以拒绝受损标记、部分未闭合语法、过期结果和传输截断，不能判断流程图逻辑、数学正确性、事实依据或是否完成了全部自然语言要求。正常结束但只生成 20 条，不会被当成传输截断。
- Mermaid 为当前实现支持的图种子集；不承诺任意 Mermaid 语法。公式以当前美元定界语法和公式渲染器为准，不承诺完整 LaTeX 或 `\(...\)` / `\[...\]` 支持。
- 人工检查公式混排截图还发现现有轻量公式渲染器的排版缺口：例如 `\bar{x}` 的上横线与字符并排，求和上下标未达到规范公式排版。块组件出现仅证明定界符被识别，不能算复杂公式的视觉正确性通过；本轮没有替换整套 LaTeX 引擎。
- 本次是小样本失败分析，没有编辑质量通过率、稳定吞吐或低配设备性能结论。复杂内容仍需在确认写回前人工核对。
