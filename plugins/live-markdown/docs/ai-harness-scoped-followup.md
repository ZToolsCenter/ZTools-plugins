日期：2026-10-23。本报告对应 B9 之后的限定修复；B9 原始场景、输出与评分保持原样。

后续对同一 B12 的 59 项浏览器回归及真实本地模型界面链路，见 [B12 补充测试](./ai-b12-test-followup.md)。补测分别保存测试断言纠正前后的记录，未修改本报告的模型质量成绩。

## 本轮边界

- 明确代码产物与唯一插入位置由程序绑定，内容模型只生成新增内容。“新增 / 添加 / 追加 / 生成”与解释代码用途的文字分开处理。
- 单一肯定续写接在当前处理范围末尾：有效选区末尾或全文末尾。显式位置、行内格式优先；禁止新增、仅询问方法、多操作及缺选区不转成全文替换。
- 来源明确列出的待办由程序固定，模型选择闭集动作，程序生成检查流程和短依据摘录。原文中的依赖清单、复核与结果记录仍须可见，已完成事项不能误当必需待办。
- 不添加自动修复重试；所有提案仍经结构检查和完整 Diff，确认前不写文档。

这些是有限契约和来源约束，不能代替开放式意图理解或领域专属方案。复杂校对、长文内容覆盖与技术方案质量不在本轮改善结论内。

## B10 发现与 B11 修复

B10 实测发现，内容要求投影把“代码块／代码围栏”当成排版控制词删掉了。模型收到的提示出现“在一个 Python”等残句，代码产物要求也随之丢失。这是程序缺陷，不能全部归因于小模型能力。

B11 只在 B10 产品基础上修复 `generationRequirements.ts`：保留代码产物和输出格式要求；从原始指令一次性合并并移除有效控制证据，避免重叠区间和偏移变化造成误删。公共 runner 回归直接捕获实际内容提示，确认语言、函数签名、返回要求和代码块要求均保留，插入位置仍由程序绑定。

B10 和 B11 的 11 个测试输入、指令及内容标准完全一致。B10 的输出、工具快照、评分和 ZIP 均保留；[B10 独立纠正记录](../.cache/acceptance/ai-common-failures/scoped-followup-v1/B10-correction-sidecar-v1.json)另行记录旧评分器把正常澄清当基础设施异常，以及漏认一处等价 clamp 表达式的问题。

同一代码用例，B10 的 0.6B 静态结果为 2/8，B11 为 7/8。该变化说明本轮提示投影修复有效；样本规模有限，不能据此声称所有复杂 Markdown 或长文任务均已解决。

唯一静态失败输出为 `return min(value, upper) if value > lower else max(value, lower)`。对有限、有序数值且 `lower <= upper`，当 `value > lower` 时标准 clamp 化为 `min(value, upper)`；否则两式均返回 `lower`。这是评分器有限表达式白名单漏判；原评分不改，不将该证明扩展到反向上下界、NaN、非数值或任意生成代码。[独立核验补充](../.cache/acceptance/ai-common-failures/scoped-followup-v1/B11-independent-verification-v1.json)保存原记录哈希、证明前提和所有 44 份记录的完整性信息。

## 验收限制

- 生成代码只作静态检查，不在插件执行。
- 本轮没有 Windows/Linux 实机环境。
- 本轮 ZTools 原生窗口连接超时；没有修改用户当前 Welcome 或恢复历史。浏览器验证不能宣称原生宿主已复测。
