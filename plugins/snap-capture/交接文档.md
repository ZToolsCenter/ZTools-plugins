## 1. 这是什么

一个自用的 ZTools 截图插件，对标「微信截图那一套」：框选 → 标注（矩形/椭圆/箭头/画笔/荧光笔/马赛克/编号/橡皮擦/文字）→ 复制 / 另存 / **悬浮置顶** → **微信 OCR 抠字** → **图片翻译**。悬浮图可拖动、裁剪、缩放、调透明度、摇一摇藏起其他贴图；贴图板统一收放；每次截图自动留历史。

**核心卖点：清晰**。画布 = 图像像素 1:1，图片绝不被放大插值；125% 副屏会重新抓物理像素图并跨屏拼接。

## 4. 架构（必读）

```
        ┌──────────────────────────────────────────┐
        │  宿主主窗口（plugin.json → main=index.html）│
        │  ┌────────────────────────────────────┐  │
        │  │ preload.js  ← 插件真正的后台         │  │
        │  │  PINS / editor / board / resultWindow│ │
        │  │  handleChildMessage() 中枢          │  │
        │  │  window.exports 入口注册（末尾）     │  │
        │  └────────────────────────────────────┘  │
        └───────────────▲──────────────────────────┘
                        │  sendToParent('zsnap:parent')  ↘ createBrowserWindow
              ┌─────────┴─────────┐
      ┌───────▼───────┐   ┌───────▼───────┐
      │ overlay/pin/  │   │ result/board  │
      │ result/board  │   │               │
      └───────────────┘   └───────────────┘
```

**铁律**
1. **每次运行结束必须 `outPlugin()`** —— 不调会停在「前台隐藏运行」态，**第二次触发永久失效**。
2. **子窗口没有插件身份**，凡「开窗/写文件/调宿主」一律经 `window.zsnap` 桥转父窗口执行。
3. **父窗口是唯一状态真相源**：`PINS`（Map）、`editor`、`board`、`resultWindow` 都在父 preload 里。

**关键实现点**
- 父子通信：子窗 `ztools.sendToParent('zsnap:parent', payload)` → 父窗 preload 的 `ipcRenderer.on(PARENT_CHANNEL, (e, payload) => handleChildMessage(e.senderId, payload))`；回信 `ipcRenderer.sendTo(senderId, CHILD_CHANNEL, payload)`。
- `isChildWindow()` 靠 `window.location.pathname` 是否匹配 `overlay|pin|result|board.html` 判断。
- **原地导航**（v1.7.8 起）：`win.loadURL(...)` 让同一扇窗变身，避免双窗口。
  - 浮窗 →「编辑标注」→ 原地变编辑器（`preload.js` `pinEdit` 分支）。
  - 编辑器 →「识别/翻译」→ 原地变结果窗（v1.8.0，`handleChildMessage` 的 `openResult` 分支）。
- **高清重抓** `grabHiRes()`（`preload.js` ~2112）：宿主 `screenCapture` 给的是 DIP 图，125% 屏会糊；该函数逐屏求物理交集 → 按物理像素裁缩略图 → `nativeImage.createFromBitmap` + Buffer 拼成统一密度大图。日志打 `hi-res: 拼接完成 WxH`。
- **清晰度铁律**：窗口内容尺寸 = 图像物理像素 ÷ 该屏 `scaleFactor`；`viewScale = Math.min(1, ...)` 永不放大。

## 5. 内存模型（重要，别被吓到）

**ZTools 每个插件窗口 = 一个独立 Electron 渲染进程，基线 130~200MB。** 这是 Electron 的地板，降不下去。

因此插件内存 ≈ **同时存活的插件窗口数 × 150MB**。已做的优化：
- 浮窗 → 编辑器：原地导航（省一个进程）
- 编辑器 → 结果窗：原地导航（v1.8.0，省一个进程）
- 结果窗互斥：开新的会关掉旧的 `resultWindow`

**仍可优化**：多张悬浮图目前是「一图一窗口」（与官方 `floating` 插件同策略）。若要贴 5 张图 → 5 个渲染进程 ≈ 750MB。想根治需把多张贴图合并到**一个透明大窗 + 多个绝对定位图元**（难点：Windows 透明大窗会吞掉桌面点击，需 `setIgnoreMouseEvents`）。

**宿主侧开关**：`out-kill-plugin` 名单里的插件会在退出后被立刻 kill（`pluginManager.ts:875`）。打开它会让截图「按了没反应」——因为插件一触发就被杀，原生框选没起来。

```bash
# 1) 改代码后递增 plugin.json 的 version（修 bug 补丁位 +1，加功能次版本位 +1）
# 2) 全量同步（禁止按扩展名筛选，否则会漏 .js / preload.js）

  --src "G:/Agent/workbuddy/2026-11-01-04-19-51/snap-plugin" \
  --install "C:/Users/Admin/.ztools/plugins/snap" \
  --delivery "G:/ztools自产插件/snap-capture"

# 3) 打包（扁平结构，根直接含 plugin.json）
python "<skill>/scripts/package_plugin.py" \
  --src "G:/ztools自产插件/snap-capture" \
  --out "G:/ztools自产插件/snap-capture-1.8.0.zip"

# 4) 重启 ZTools，真机冒烟
```

**每次交付后必做校验**（脚本已内置）：三处目录逐文件 md5 一致 + zip 内 `plugin.json`/`preload.js` 与工程源一致。

> ⚠️ **历史教训**：曾用 `cp $SRC/*.{html,png,json,md}` 同步，漏掉 `.js`，导致 v1.7.5~1.7.7 对 `preload.js` 的修改**一次都没送达**用户机器，用户连续反馈「改了没生效 / 双窗口还在 / 编辑窗跟桌面融为一体」。排查任何「bug 没修好」前，**先确认安装目录里 preload.js 的哈希是不是最新的**。
